## 결정

기술 식별자는 OrdinalIgnoreCase로 비교한다. 성경 이름은 선택한 항목을 제외한 실제 이름과 전체 일치로 판단한다. 네이티브 문자열 인수는 Windows Unicode 계약을 따른다. 내부 자료구조에는 이미 생성하는 형식을 사용하고 WPF 바인딩과 외부에 노출된 계약은 호출자를 확인한다. PPT COM 객체의 생성·종료 경계와 송출 모니터 좌표는 유지한다. SQLite 검증에는 메모리 DB를 사용한다.

## 호출자 및 데이터 호환성

WPF 공용 큐 모델 `LiveQueueItem`과 `LiveItemKinds`를 두 화면 계층이 함께 참조하는 `Easislides.Wpf` 네임스페이스에 둔다. 저장소는 기존 DTO와 항목 종류 문자열을 사용한다. 이 어셈블리를 직접 참조하는 외부 코드가 있으면 새 네임스페이스를 가져와 다시 빌드해야 한다. `WorshipListRtfExporter.BuildRtf`와 인스턴스 상태가 필요 없는 폼 도우미는 형식에서 호출한다. 옛 전역 `SHFILEOPSTRUCT` 사본을 정리하고 WinForms는 `Easislides.SHFILEOPSTRUCT`를 사용한다. 공개 메인 창 접근자는 읽기만 허용한다.

## Windows API 및 스키마

목록에서 실제로 사용하는 파일의 존재를 먼저 확인하고, 확장자별로 Windows Unicode 파일 연결을 조회한다. 기존 Win32 장치 호출은 관리 코드로 감싸고, 가변 길이 속성은 바이트 버퍼와 반환된 길이·형식에 따라 해석한다. 장치 알림 및 속성 변경 호출은 테스트 중 장치 상태를 바꾸지 않도록 읽기 경로와 분리했다.

SQLite는 TIMING과 MSC 추가를 한 트랜잭션에서 실행하고, 과거에 둘 중 한 열만 만들어진 SONG 테이블도 시작 시 복구한다. DB가 읽기 전용이면 스키마 검사에서 실패를 반환한다.

## 메모리 사용

개수가 정해진 가사 미리보기 카드는 최종 길이 배열에 직접 채우고 빈 결과는 공유 빈 배열을 반환한다. 성경 선택은 선택 한도를 적용한 한 번의 복사로 완성한다. 검색·곡 병합처럼 실제 반환 자료형이 여러 개인 경로에서는 읽기 전용 인터페이스를 유지한다.
