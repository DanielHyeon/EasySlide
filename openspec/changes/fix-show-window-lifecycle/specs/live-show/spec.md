# live-show

## ADDED Requirements

### Requirement: 송출 창이 스스로 닫혀도 쇼는 정상 경로로 끝난다

메인 화면이 기다리지 않는 방식의 쇼(모니터 둘)에서 송출 창이 메인 화면의 조작 없이 닫히려 하면, 앱은 메인 화면의 쇼 종료 처리를 정확히 한 번 실행해야 한다(SHALL). 송출 창은 폐기되지 않아야 한다(SHALL NOT).

#### Scenario: 송출 창을 직접 닫는다

- **GIVEN** 쇼가 진행 중이다
- **WHEN** 송출 창에 창 닫기 요청이 온다
- **THEN** 쇼가 끝나고, 메인 화면의 쇼 버튼이 꺼진 상태가 되고, 상태 줄이 `Show: OFF`가 된다
- **AND** 예배 순서 목록의 표시가 `LIVE`에서 `OUT`으로 바뀐다
- **AND** 종료 처리는 한 번만 실행된다

#### Scenario: 그 뒤 쇼를 다시 시작한다

- **GIVEN** 송출 창이 스스로 닫혀 쇼가 끝났다
- **WHEN** 쇼 버튼을 누른다
- **THEN** 쇼가 정상으로 시작되고 앱이 계속 응답한다
- **AND** PPT 항목이 송출 중이었어도 마찬가지다

#### Scenario: 앱을 종료한다

- **WHEN** 쇼 진행 중에 앱을 닫거나 Windows가 종료된다
- **THEN** 송출 창은 지금처럼 닫히고, 닫기가 막히지 않는다

#### Scenario: 메인 화면에서 끝낸다

- **WHEN** 쇼 버튼, F12, 송출 창의 Esc로 쇼를 끝낸다
- **THEN** 이 수정 전과 같이 동작하고, 종료 처리는 한 번만 실행된다

### Requirement: 송출 창을 예외 때문에 바꿔 끼우지 않는다

메인 화면이 송출 창에 조작을 전달하다 예외가 나도, 화면에 떠 있는 송출 창을 다른 창으로 바꿔서는 안 된다(SHALL NOT). 송출 창이 실제로 폐기된 경우에만 새로 만든다(SHALL).

#### Scenario: 조작 전달 중 예외

- **GIVEN** 쇼가 진행 중이다
- **WHEN** 알림, 슬라이드 이동 등 조작을 전달하다 예외가 난다
- **THEN** 예외가 기록되고, 송출 창은 그대로이며, 그 뒤의 조작이 계속 프로젝터에 반영된다

### Requirement: 처리되지 않은 예외가 보이지 않는 창에서 앱을 세우지 않는다

UI 스레드에서 처리되지 않은 예외가 나면 앱은 그것을 기록하고 메인 화면에서 알려야 한다(SHALL). 출력 모니터에만 보이는 창에서 입력을 기다리면 안 된다(SHALL NOT).

#### Scenario: 송출 창에서 예외가 난다

- **WHEN** 송출 창의 처리 중 처리되지 않은 예외가 난다
- **THEN** 예외가 앱 기록에 남는다
- **AND** 메인 화면에 오류가 났다는 표시가 보이고, 메인 화면은 계속 조작할 수 있다

#### Scenario: 알림이 계속 보인다

- **GIVEN** 쇼가 진행 중이다
- **WHEN** 처리되지 않은 예외가 난다
- **THEN** 메인 화면 상태 줄의 알림 칸에 오류 표시가 나오고, 운영자가 클릭해 지울 때까지 남는다
- **AND** 같은 예외가 되풀이되면 횟수만 올라가고, 기록 파일에는 처음 것의 전체 내용이 남아 있다

#### Scenario: 앱을 켜는 도중의 예외

- **WHEN** 메인 화면이 다 뜨기 전에 처리되지 않은 예외가 난다
- **THEN** 지금까지처럼 창으로 알린다

### Requirement: 화면은 그림 버퍼를 서로 나눠 쓰지 않는다

미리보기, 송출 단, 송출 창은 글자와 패널을 그릴 때 각자의 버퍼를 써야 한다(SHALL). 한 화면이 닫히거나 크기가 바뀌거나 다른 내용을 그려도 다른 화면이 그리던 것에 영향을 주면 안 된다(SHALL NOT).

#### Scenario: 송출 창이 폐기된 뒤

- **WHEN** 송출 창이 폐기된 뒤 메인 화면에서 가사 항목을 선택한다
- **THEN** 미리보기가 정상으로 그려지고 예외가 나지 않는다

#### Scenario: 화면 크기가 서로 다르다

- **GIVEN** 송출 창의 크기가 미리보기, 송출 단의 그림 크기와 다르다 (앱을 켠 뒤 프로젝터를 연결한 경우 등)
- **WHEN** 미리보기와 송출 창이 번갈아 그린다
- **THEN** 어느 화면에서도 예외가 나지 않고, 각 화면은 자기 크기로 그려진다

#### Scenario: 송출 창이 전환 효과를 그리는 동안

- **GIVEN** 송출 창이 전환 효과로 다음 슬라이드를 그리고 있다
- **WHEN** 그 사이에 미리보기에서 다른 항목을 선택한다
- **THEN** 프로젝터에는 송출 중인 항목의 글자만 보인다. 미리보기의 글자가 섞여 보이지 않는다

### Requirement: 그리기 예외가 화면을 죽이지 않는다

화면을 그리다 예외가 나도 그 화면은 다음 그리기에서 다시 그려져야 한다(SHALL). 예외는 기록된다.

#### Scenario: 한 프레임이 실패한다

- **WHEN** 송출 화면을 그리다 한 번 예외가 난다
- **THEN** 그 뒤 슬라이드를 넘기면 화면이 정상으로 그려진다 (빨간 X로 남지 않는다)
- **AND** 실패한 프레임 대신 그 화면이 마지막으로 완성한 그림이 보인다 (검은 화면이 되지 않는다)
- **AND** 메인 화면의 알림 칸에 어느 화면의 그리기가 실패했는지 나온다

#### Scenario: 그리기가 계속 실패한다

- **WHEN** 한 화면의 그리기가 매번 실패한다
- **THEN** 다시 그리기는 연달아 세 번까지만 시도되고, 화면에는 마지막으로 완성한 그림이 남는다

### Requirement: 송출 창이 뜨다 실패하면 메인 화면이 쇼를 켜진 것으로 두지 않는다

송출 창이 처음 뜨는 도중 실패하면 앱은 메인 화면을 쇼가 꺼진 상태로 되돌리고 알려야 한다(SHALL). 그 뒤 쇼를 다시 시작할 수 있어야 한다(SHALL).

#### Scenario: 송출 창의 초기화가 실패한다

- **WHEN** 쇼 버튼을 눌렀는데 송출 창이 초기화 도중 예외를 낸다
- **THEN** 쇼 버튼이 꺼진 상태가 되고 상태 줄이 `Show: OFF`이며, 알림 칸에 오류가 나온다
- **AND** 초기화되지 않은 창이 화면에 남지 않는다
- **AND** 쇼 버튼을 다시 누르면 쇼가 정상으로 시작된다
