# Proposal: 송출 창이 닫히거나 오류가 날 때 메인 화면과 어긋나는 문제 수정

## Why

송출 창(`FrmLaunchShow`)과 메인 화면(`FrmMain`)이 서로의 상태를 놓치는 경우가 여러 개 확인됐다. 모두 이번 작업 이전부터 있던 문제다.

1. **송출 창이 스스로 닫히면 메인 화면이 모른다.** 창 닫기 등으로 송출 창이 닫히면 쇼 버튼이 눌린 채로 남는다. 메인 화면의 종료 처리(`GoLive(false)`)가 실행되지 않기 때문이다.
2. **그 뒤 쇼를 다시 시작하면 앱이 멈춘다.** 시험에서 두 번 재현됐다. 코드로 본 경위: 스스로 닫힌 송출 창은 폐기된 상태다. 쇼를 다시 시작하면 `Start_Presentation`이 폐기된 창을 보여 주려다 예외가 나고, 그 예외를 잡아 새 창을 만든다. 새 창은 평소(같은 창을 다시 쓰는 경로)와 다른 초기화 경로를 탄다. 이때 멈춘 화면에는 송출 창 위에 뜬 작은 창이 있었다. 처리되지 않은 예외를 알리는 창으로 추정한다. 이 창이 출력 모니터에서 PowerPoint 슬라이드 쇼 뒤에 가려져 있어 앱이 멈춘 것처럼 보인다. 어떤 예외인지는 아직 모른다.
3. **조작 도중 예외가 나면 송출 창을 바꿔 끼운다.** `FrmMain.RemoteControlLiveShow`는 어떤 예외든 잡으면 새 `FrmLaunchShow`를 만들어 `LiveShow`에 넣고 다시 시도한다. 새 창은 화면에 뜬 적이 없고, 프로젝터에 떠 있는 원래 창은 버려진 채 남는다. 그 뒤 메인 화면의 조작은 프로젝터에 반영되지 않는다.
4. **처리되지 않은 예외가 보이지 않는 곳에 창을 띄운다.** 앱에 UI 스레드 예외 처리기가 없다. 기본 동작은 계속/종료를 묻는 창인데, 지금 활성인 창 위에 뜬다. 송출 창에서 난 예외라면 출력 모니터에 뜨고 운영자는 보지 못한다.
5. **슬라이드가 자동으로 넘어가면 송출 단 썸네일의 선택 테두리가 따라오지 않는다.** 자동 넘김으로 슬라이드가 바뀌면 송출 창이 메인 화면에 알리는데(`Remote_SlideChanged`), 이 경로는 PPT 썸네일의 선택을 갱신하지 않는다. 작업 2의 적대적 리뷰에서 확인했다.

## What Changes

- 송출 창이 스스로 닫히려 하면, 닫는 대신 메인 화면의 정상 종료 경로를 탄다. 창은 폐기되지 않고 숨겨지므로 다시 시작할 수 있다.
- 쇼를 시작할 때 송출 창이 없거나 폐기됐는지를 예외가 아니라 직접 확인해서 새로 만든다.
- `RemoteControlLiveShow`는 예외가 났다고 송출 창을 바꿔 끼우지 않는다. 창이 실제로 폐기된 경우에만 새로 만든다.
- UI 스레드에서 처리되지 않은 예외는 기록하고, 운영자가 볼 수 있는 메인 화면에 알린다. 보이지 않는 곳에서 입력을 기다리며 멈추지 않는다.
- 2번의 예외가 무엇인지 확인하고 원인을 고친다. 확인된 원인은 세 화면이 그림 버퍼를 함께 쓰는 구조다. 화면마다 자기 버퍼를 갖게 한다 (design.md L1).
- 그리기 예외 한 번으로 화면이 죽지 않게 한다 (L2).

5번(자동 넘김과 썸네일 선택)은 이 변경에서 뺐다. 그 경로는 PPT 항목에서 실행되지 않는다는 것이 리뷰에서 확인됐다 (design.md L5).

## Out of Scope

- 모니터가 하나일 때의 쇼 진행 방식(메인 화면이 기다리는 방식)
- 쇼 도중 예배 목록이 바뀐 것을 송출 창에 알리는 것
