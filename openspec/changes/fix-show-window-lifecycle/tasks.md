# Tasks: 송출 창이 닫히거나 오류가 날 때 메인 화면과 어긋나는 문제 수정

구현 → 적대적 리뷰 → 내장 코드 리뷰 → 총괄 검증 → 커밋.

## 1. 먼저 확인할 것

- [x] 1.1 송출 창이 스스로 닫힌 뒤 쇼를 다시 시작할 때 무슨 예외가 나는지 확인한다. 임시 기록(처리되지 않은 예외와 첫 예외 기록)을 넣은 빌드로 재현하고, 예외의 종류와 위치를 적는다. 임시 기록은 끝나면 지운다
- [x] 1.2 멈춘 화면의 작은 창이 무엇인지 확인한다 (자식 컨트롤의 글자를 읽는다)

## 2. 송출 창의 닫힘

- [x] 2.1 메인 화면이 기다리지 않는 쇼에서 송출 창이 스스로 닫히려 하면 닫기를 취소하고, 메인 화면의 종료 경로(`Remote_EndShow` → `GoLive(false)` → `StopShow`)를 메시지로 예약한다. 닫는 처리 안에서 바로 부르지 않는다 (바로 부른 시험에서 앱이 응답하지 않았다)
- [x] 2.2 앱 종료, Windows 종료, 소유 창이 닫히는 경우에는 막지 않는다
- [x] 2.3 `Start_Presentation`: 송출 창이 없거나 폐기됐으면 새로 만든다. 예외를 잡아서 만드는 방식을 없앤다. 새로 만든 창의 초기화 경로가 다시 쓰는 창의 경로와 같은 결과를 내는지 확인하고, 1.1에서 찾은 원인을 고친다

## 3. 예외 처리

- [x] 3.1 `RemoteControlLiveShow`: 예외가 나면 기록한다. 송출 창을 새로 만들어 다시 시도하는 것은 창이 실제로 폐기된 경우로 한정한다
- [x] 3.2 UI 스레드의 처리되지 않은 예외를 받는 처리기를 둔다. 예외를 앱 기록에 남기고, 메인 화면에 알린다 (메인 화면을 막지 않는 방식). 처리기 자체가 예외를 내지 않게 한다

## 4. 썸네일 선택

- [ ] 4.1 (취소) `Remote_SlideChanged` 경로에서도 송출 단 PPT 썸네일의 선택이 지금 슬라이드로 옮겨 가게 한다. 6.5에서 뺐다. 그 경로는 PPT 항목에서 실행되지 않는다

## 7. 2차 리뷰 반영

- [x] 7.2 그리기 실패를 알림 칸에 올린다. 실패한 전환은 끝난 것으로 처리해 전환 타이머를 멈춘다
- [x] 7.3 알림 칸이 항상 상태 줄 안에 들어가게 한다. 긴 메시지는 말줄임표로 끝낸다. 알림이 떠 있어도 출력 모니터 칸이 보인다

- [x] 7.5 기록을 줄이는 열쇠에 우리 코드의 첫 스택 프레임을 넣는다. 알림 횟수는 지우면 0부터 다시 센다
- [x] 7.6 송출 창이 스스로 정리하고 숨은 경우에도 메인 화면의 쇼 버튼과 표시를 꺼진 상태로 맞춘다
- [x] 7.7 글자를 그리다 예외가 나면 그 화면의 버퍼가 반쯤 그려진 채 남지 않게 한다 (이전 내용을 유지하거나, 다음 전환이 빈 화면에서 시작하지 않게 한다)
- [x] 7.8 주석을 실제 동작에 맞춘다 (`OnPaint`, `ErrorNoticeWidth`, `Program.cs`)

## 10. 코드 리뷰 반영

- [x] 10.1 모니터 둘 방식에서 송출 창이 처음 뜨다 실패하면 메인 화면을 꺼진 상태로 되돌리고 알린다. 실패한 창은 폐기해 다음 시작 때 새로 만든다 (초기화 중의 예외는 `Show()` 밖으로 나오지 않으므로 `Show()` 뒤에 초기화가 끝났는지 확인한다. 10.4, 10.5에서 고쳐 썼다)
- [x] 10.2 화면 합성이 실패하면 새로 만든 비트맵과 Graphics를 해제한다
- [x] 10.3 문 열림/닫힘 전환 프레임이 실패해도 그 프레임의 작업용 비트맵을 해제한다

- [x] 10.4 실패한 쇼 시작을 끝내기 버튼과 같은 경로로 정리한다 (쇼가 진행 중인 것으로 둔 채). 정리 도중 예외가 나도 메인 화면은 꺼진 상태로 끝난다
- [x] 10.5 다시 띄우는 창의 초기화 실패도 잡는다 (`StartInitCompleted`). Load가 끝난 적 없는 창만 폐기하고 바로 새 창을 만든다
- [x] 10.6 모니터 하나 방식에서 Load가 실패한 창을 쇼가 끝난 뒤 새 창으로 바꾼다
- [x] 10.7 실패 한 번에 알림 한 번

## 11. 확인 못 한 것

- 마지막 빌드(10.4~10.7 반영)의 총괄 검증. 그 직전 빌드까지는 총괄이 가사 항목과 PPT 항목으로 직접 확인했다. 마지막 빌드는 구현 담당의 실행 결과만 있다 (모니터가 꺼져 있어 다시 실행하지 못했다). 10.5의 새 창 만들기와 10.6은 빌드만 확인했다
- 실패한 시작 뒤 화면 보호기 설정이 복원되는 것 (이 PC는 화면 보호기가 꺼져 있어 관찰할 수 없다)
- 정리 도중 예외가 났을 때의 반복 단계 (어느 실행에서도 그 경로를 타지 않았다)

- 알림의 풍선 도움말이 실제 화면에 뜨는 것 (테스트 창이 활성 창이 아니어서 보지 못했다. 같은 방식의 별도 프로그램에서는 떴다)
- 창이 좁을 때 상태 줄 칸이 줄어드는 경로 (코드로만 따졌다)
- 눈에 보이는 전환 효과 중의 실패 처리 (이 PC의 전환 설정이 "없음"이다)
- PPT 슬라이드가 출력 모니터에 실제로 보이는 것 (검증 때 출력 모니터에 다른 앱 창이 있었고, 슬라이드 쇼 창이 그 뒤에 떴다. 별도 문제로 조사한다)
