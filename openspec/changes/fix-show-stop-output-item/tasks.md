# Tasks: 쇼를 끝낼 때 송출 항목 정보가 어긋나는 문제 수정

구현 → 적대적 리뷰 → 내장 코드 리뷰 → 총괄 검증 → 커밋.

- [x] 1 `FormClosingCleanup`: 모니터가 둘일 때는 `Gf.LiveItem`의 값을 `Gf.OutputItem`에 되쓰지 않는다. 모니터가 하나일 때는 그대로 둔다
- [x] 2 모니터가 둘일 때 쇼 도중 메인 화면이 `OutputItem`을 빠짐없이 갱신하는지 다시 확인한다 (슬라이드 이동, 항목 전환, 간격 항목, 자동 넘김). 빠진 경로가 있으면 1을 적용하지 말고 보고한다
- [ ] 3 송출 창이 스스로 닫힐 때(메인 화면의 종료 경로를 거치지 않은 경우) 메인 화면의 쇼 종료 처리를 한 번 실행한다. 종료 처리가 서로를 다시 부르지 않게 한다
  - 이 변경에서는 하지 않았다. 닫는 처리 안에서 종료 경로를 바로 부르는 방식을 시험했더니, 그 뒤 쇼를 다시 시작할 때 앱이 응답하지 않았다. 다시 시작할 때의 멈춤은 이 수정 없이도 재현된다. `fix-show-window-lifecycle`에서 원인 확인과 함께 다룬다
  - 되쓰기 조건은 `Gf.DualMonitorMode`가 아니라 송출 창의 `Modal`로 정했다 (메인 화면이 기다리는 방식의 쇼에서만 되쓴다). 모니터가 하나인 PC도 보통은 기다리지 않는 방식으로 쇼를 띄운다
- [x] 4 빌드 확인
- [x] 5 실행 확인 (시험용 예배 목록): 쇼 도중 송출 항목을 위로 옮기고 쇼를 끝낸 뒤, 송출 위치와 목록 표시가 맞는지 본다. 목록을 바꾸지 않고 끝내는 경우도 본다. "현재 항목 다시 시작"은 자동 넘김 설정을 바꾸므로 누르지 않는다
