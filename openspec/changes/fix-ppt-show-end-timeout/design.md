# Design: PowerPoint가 멈춰 있어도 쇼를 끌 수 있게 한다

## 확인된 것 (조사, 2026-11-17)

- 쇼 끄기의 경로: `FrmMain.GoLive(false)` → `FrmLaunchShow.StopShow` → `FormClosingCleanup` → `Gf.ClearUpPowerpointWindows` → `OfficeLib/PowerPoint.cs`의 `ClearUpPowerpointWindows` (프레젠테이션 수, 항목, `FullName`, 태그 읽기, `Close()`), 이어서 조건에 따라 `QuitPowerPointApp`. 모두 메인 화면 스레드에서 다른 프로세스(PowerPoint)로 가는 COM 호출이고 시간 제한이 없다. 저장소에 COM 메시지 필터는 없다.
- 앱을 닫을 때의 `Gf.ShutdownPowerpoint`도 같은 호출을 쓴다.
- PowerPoint 프로세스를 멈춰 놓으면(suspend) 쇼 끄기가 돌아오지 않는다.
- 쇼 끝에서 슬라이드 쇼 창을 내리는 일은 이미 비동기로 한다. 작업 표시줄 복원(`ShowTaskBar`)은 탐색기 창에 동기 `SetWindowPos`를 보낸다.

## Decisions

### T1. 먼저 응답하는지 확인한다

쇼 끝과 앱 닫기에서 PowerPoint에 COM 요청을 보내기 전에, 앱이 쓰는 PowerPoint의 창에 짧은 시간 제한(약 1초)을 둔 확인 메시지를 보낸다 (`SendMessageTimeout`, `WM_NULL`, 응답 없는 창이면 바로 포기). 어느 창에 보낼지(PowerPoint의 주 창, 슬라이드 쇼 창)와, 창이 하나도 없을 때의 판단은 구현에서 정한다. 창 핸들을 COM으로 묻지 않고 구할 수 있어야 한다 (이미 제목으로 창을 찾는 코드가 있다).

- 응답하면 지금처럼 정리한다.
- 응답하지 않으면 COM 정리를 하지 않는다. 기록하고 알림 칸에 알린다 ("PowerPoint가 응답하지 않아 닫지 못했다"는 뜻의 영어 문구). 쇼 끄기의 나머지(송출 창 숨기기, 화면 보호기와 작업 표시줄 복원, 메인 화면의 상태)는 그대로 실행한다.

### T2. 확인을 통과한 뒤의 요청에도 시간 제한을 둔다

확인 직후에 PowerPoint가 멈출 수도 있다. 쇼 끝과 앱 닫기의 PowerPoint 호출 묶음 전체에 시간 제한(약 5초)을 둔다. 방법은 구현에서 고른다. 후보:

- 메인 화면 스레드에 COM 메시지 필터를 걸어, 제한을 넘은 호출을 취소한다 (취소된 호출은 예외가 된다).
- 그 밖에 메인 화면 스레드를 막지 않는 방법.

고른 방법은 PowerPoint를 일부러 멈춰 놓는 시험으로 확인한다. 어느 방법으로도 안전하게 제한할 수 없으면 T1만 넣고 그 이유를 적는다. 제한을 넘어 포기한 경우도 T1의 "응답 없음"과 같이 처리한다.

메시지 필터를 쓴다면: 쇼 끝과 앱 닫기의 호출 구간에서만 걸고 끝나면 원래 필터로 되돌린다. PowerPoint가 "바쁨"으로 거절한 호출을 다시 시도하는 기존 처리(`IsPowerPointBusy`)와 어긋나지 않게 한다. 취소 뒤에 PowerPoint 쪽 객체를 다시 쓰지 않는다 (참조를 놓고, 다음에 새로 붙는다).

### T3. 못 한 정리는 나중에 다시 시도한다

- 정리를 건너뛰었거나 포기했으면 그 사실을 기억한다. 다음 쇼를 시작할 때(이미 남은 슬라이드 쇼 창을 내리는 자리)와 앱을 닫을 때 다시 시도한다. 그때도 T1, T2를 따른다.
- 닫지 못한 쇼 복사본이 남아 있어도 다음 쇼가 그 복사본이나 같은 이름의 다른 것을 잘못 쓰지 않는지 확인한다 (`fix-ppt-small-items`의 태그 확인이 맡는다).
- 앱을 닫을 때도 응답이 없으면 PowerPoint를 그대로 두고 앱은 닫힌다. 강제 종료하지 않는다. 앱이 띄운 숨은 PowerPoint가 남을 수 있다는 것을 기록에 남긴다.

### T4. 쇼 상태가 PowerPoint 정리에 묶이지 않게 한다

쇼를 끌 때 송출 창 숨기기와 메인 화면의 상태 갱신이 PowerPoint 정리보다 먼저 일어나게 순서를 바꿀 수 있는지 본다. 쇼 창 수명 주기(`fix-show-window-lifecycle`)의 규칙과 어긋나지 않을 때만 바꾼다. T1, T2가 있으면 정리는 몇 초 안에 끝나므로, 순서를 바꾸는 것이 위험하면 그대로 둔다.

작업 표시줄 복원은 탐색기가 응답하지 않아도 막히지 않게 한다 (`SWP_ASYNCWINDOWPOS`).

## 시험 방법

- PowerPoint를 멈춰 놓는 시험: 시험 인스턴스가 띄운 POWERPNT 프로세스(이번 실행에서 생긴 것인지 시작 시각으로 확인)를 멈춘(suspend) 뒤 쇼를 끈다. 기대: 몇 초 안에 쇼 버튼이 꺼지고, 알림이 나오고, 메인 화면이 계속 응답하고, 앱을 닫을 수 있다. 다시 풀어 주고(resume) 쇼를 다시 시작하면 정상으로 동작하고 남은 복사본이 정리된다.
- 확인 직후에 멈추는 경우(T2): 임시 스위치로 확인과 정리 사이에 틈을 만들고 그 사이에 멈춘다.
- 정상 경로: 쇼 끄기와 앱 닫기에 걸리는 시간이 수정 전과 같다. 출력 모니터의 화면이 같다.
- 사용자의 PowerPoint가 따로 떠 있는 경우는 이 PC에서 만들지 않는다 (사용자 자료). 코드로 확인한다.

## 구현하면서 정한 것 (2026-11-17)

- **T1 응답 확인** (`PowerPoint.ProbePowerPoint`): COM 없이 이 세션의 POWERPNT 프로세스를 찾고, 프로세스마다 주 창(`PPTFrameClass`, 앱이 띄운 숨은 PowerPoint에도 있다) 하나에 `SendMessageTimeout(WM_NULL, SMTO_ABORTIFHUNG)`을 보낸다. 결과는 넷이다: 프로세스 없음(정리 진행, 호출은 바로 실패한다), 응답함, 모름(창이 없거나 보내기가 바로 실패함: 시간 제한 아래에서 진행), 응답 없음(시간 초과 `ERROR_TIMEOUT` 또는 `IsHungAppWindow`). 멈춘 PowerPoint는 제한 시간을 다 쓰고 오류 1460을 돌려준다.
  - 제한 시간: 쇼 끝과 쇼 시작의 재시도는 1초. 앱 닫기는 3초(여기서 잘못 포기하면 숨은 PowerPoint가 남는다), Windows 세션 종료 중이면 1초.
  - PowerPoint 호출이 하나도 없을 쇼 끝(가사 항목만의 쇼)에서는 확인하지 않는다.
- **T2 시간 제한** (`OfficeLib/PowerPointCallLimit.cs`): 호출 묶음 동안만 메인 화면 스레드에 COM 메시지 필터를 건다. 묶음 안의 호출이 **5초 동안 하나도 끝나지 않으면**, 또는 묶음 전체가 30초를 넘으면 기다리는 호출을 취소한다(`RPC_E_CALL_CANCELED`). 처음에는 묶음 전체에 5초를 두었으나, PPT 항목이 많거나 PC가 느리면 정상인 PowerPoint도 넘길 수 있어 "진행이 없는 시간"으로 바꾸었다. 필터는 메시지가 올 때만 불리므로 묶음 동안 0.1초마다 스레드에 `WM_NULL`을 보낸다. 묶음이 끝나면 이전 필터로 되돌린다. "바쁨" 거절의 처리는 이전 필터(없으면 COM 기본)와 같다.
- **참조를 놓는 일은 취소할 수 없다.** 멈춘 PowerPoint에 대한 참조 해제는 PowerPoint가 풀릴 때까지 돌아오지 않고 필터로도 끊기지 않는다(시험 프로그램에서 확인). 그래서 포기한 뒤에는 참조를 놓지 않고 따로 쥐고 있다가(`heldProxies`), 나중에 PowerPoint가 응답한 것을 확인한 뒤에 놓는다. 앱 닫기에서 끝까지 응답이 없으면 아무것도 놓지 않고 닫는다. 앱 닫기의 마지막 참조 해제 직전에도 한 번 더 확인한다.
- **T3 다시 시도**: 닫지 못한 쇼 복사본은 별도 목록(`pendingShowCopies`)으로 옮긴다. 다음 쇼는 새 복사본을 새 이름으로 연다. 다시 시도는 쇼 시작(미리 열기 전)과 앱 닫기에서 하고, 이름과 표식이 모두 맞는 것만 닫는다. 쇼 시작의 재시도는 PowerPoint를 종료하지 않는다(바로 이어서 미리 열기가 PowerPoint에 붙는다). 앱 닫기의 재시도는 종료까지 한다. 다시 붙지 못하면 목록을 그대로 둔다. 건너뛴 경우에도 다른 화면이 기억하던 쇼 복사본 이름을 무효로 한다(`ForgetShowCopyNames`).
- **알림**: 쇼 끝에서 복사본을 닫지 못했을 때 "PowerPoint is not responding: the show's PowerPoint copy could not be closed (tried again at the next show start)". 복사본은 다 닫고 종료 단계에서만 끊긴 경우는 기록만 한다. 재시도에 성공해도 앞의 알림은 알림 칸의 평소 규칙대로 남는다.
- **T4**: `HideTaskBar` / `ShowTaskBar`에 `SWP_ASYNCWINDOWPOS`를 더했다. `StopShow` 안의 순서는 바꾸지 않았다(모달 쇼 창을 정리 전에 숨기면 `ShowDialog`가 쇼 끄기 도중에 끝난다). 쇼 끄기가 1초 이상 걸리면 걸린 시간을 기록한다.

## 확인한 것 (PowerPoint 프로세스를 일부러 멈추는 시험)

| 경우 | 결과 |
|---|---|
| 수정 전: 멈춘 채 쇼 끄기 | 쇼 끄기 요청이 34초 뒤 시간 초과, 앱이 응답하지 않음 |
| 멈춘 채 쇼 끄기 | 확인 약 1초, 쇼 끄기 전체 약 1.04초. 쇼 버튼 꺼짐, 알림 표시, 앱 응답 |
| 그 상태로 앱 닫기 | 닫힘 (평소보다 약 3초 더). PowerPoint는 그대로 남음 |
| 재개 뒤 쇼 다시 켜기 | 남은 복사본 9개 중 9개 닫힘, 슬라이드 쇼 창 1개, 이어서 정상 끄기, 앱을 닫은 뒤 PowerPoint 없음 |
| 재개 뒤 바로 앱 닫기 | 남은 복사본 9개 닫힘, PowerPoint 종료됨 |
| 확인 직후에 멈춤 | 마지막으로 끝난 호출로부터 약 5초 뒤 포기, 알림. 다시 시도에서 나머지 닫힘 |
| 느리지만 정상 (닫기마다 0.7초 지연, 합계 7초) | 끝까지 정리, 알림 없음 |
| 정상 경로의 시간 (수정 전과 번갈아) | 쇼 끄기, 쇼 켜기, 앱 닫기 모두 차이 없음. 가사만의 쇼도 같음 |

## Known Limitations

- **쇼를 다시 켜면 여전히 멈춘다.** PowerPoint가 계속 응답하지 않는 채로 쇼를 다시 시작하면, 재시도는 알림만 내고 이어지는 PPT 미리 열기(`PreLoadPowerpointFiles`)에서 앱이 멈춘다. 쇼 진행 중의 슬라이드 이동, 항목 불러오기, 미리보기 썸네일도 PowerPoint의 답을 제한 없이 기다린다. 별도 변경으로 다룬다.
- **프로젝터에 멈춘 슬라이드가 남는다.** PowerPoint가 응답하지 않으면 그 슬라이드 쇼 창은 앱이 치울 수 없다. PowerPoint가 다시 응답해도 다음 쇼 시작이나 앱 닫기까지 (맨 위에서는 내려간 채로) 보인다.
- 확인과 참조 해제 사이에 PowerPoint가 멈추면 그 해제는 기다린다 (취소할 수 없다).
- POWERPNT 프로세스가 여럿이면 하나만 응답하지 않아도 정리를 건너뛴다 (앱의 참조가 어느 프로세스로 가는지 호출 없이는 알 수 없다).

## 확인하지 못한 것 (코드로만 확인)

- 종료 단계에서만 끊기는 경우, 다시 붙기에 실패하는 경우, 확인 메시지가 바로 실패하는 경우
- Windows 세션 종료 중의 앱 닫기 (1초 확인)
- 사용자가 따로 띄운 PowerPoint가 있는 경우, POWERPNT 프로세스가 여럿인 경우
- 단일 모니터의 모달 쇼
