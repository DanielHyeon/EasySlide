# Design: 남은 자원 정리 문제 수정

## 원인 기록 (작업 1.1)

### 관찰한 것

- 앱은 시작할 때 PowerPoint를 띄운다. `gfConfig.cs`가 `LivePP`, `PreviewPPT`, `OutputPPT`, `ExternalPPT`를 백그라운드에서 초기화하고, `FrmMain` 생성자가 `MainPPT`를 초기화한다. PowerPoint는 프로세스가 하나뿐이라 다섯 개가 같은 프로세스를 가리킨다.
- 수정 전 종료 경로(`Form1_FormClosing` → `Gf.ClearUpPowerpointWindows`)는 `LivePP`의 연결로 `Quit()`만 호출했다. 나머지 네 연결은 해제하지 않았다.
- 수정 전 빌드: PPT 항목을 미리 본 뒤 앱을 닫으면, 앱 프로세스가 끝나고 20초가 지나도 창 없는 `POWERPNT.EXE`가 남는다 (총괄이 직접 실행해 확인).
- 수정 후 빌드: 같은 순서로 실행하면 종료 2초 뒤에 `POWERPNT.EXE`가 없다 (총괄이 직접 실행해 확인. 송출 단 복사 포함).

### 확정하지 못한 것

왜 남는지에 대한 설명은 두 실험이 서로 다르다.

- 구현 쪽 실험: 다른 연결이 살아 있는 채로 `Quit()`을 부르고 클라이언트가 해제 없이 끝나면 PowerPoint가 끝나지 않는다.
- 리뷰 쪽 실험: 같은 조건에서 PowerPoint는 클라이언트가 끝나고 약 5초 뒤에 스스로 끝난다.

두 실험은 호출 방식(NetOffice / PowerShell COM)과 스레드 모델이 다르다. 어느 쪽이 앱의 상황과 같은지는 가리지 못했다.
따라서 "모든 연결을 종료 때 해제하면 PowerPoint가 남지 않는다"는 **실제 앱에서 수정 전후를 비교해 확인한 사실**이고, 그 원리는 추정이다.

## Decisions

### D1. 종료할 때 다섯 연결을 모두 해제한다

`Gf.ShutdownPowerpoint`가 기존 정리(`ClearUpPowerpointWindows`)를 한 뒤 다섯 래퍼의 연결을 해제한다. 래퍼 객체 자체는 null로 만들지 않는다. 종료 도중 늦게 들어오는 호출이 null 래퍼를 만나지 않게 하기 위해서다.

### D2. 앱이 열지 않은 프레젠테이션은 닫지 않는다

- `QuitPowerPointApp`은 열린 프레젠테이션이 하나도 없을 때만 `Quit()`을 부른다. 개수를 읽지 못하면 부르지 않는다.
- `ClearUpPowerpointWindows`는 앱이 연 것(`PowerpointList`에 있는 것)만 닫는다.
- 앱을 시작할 때 실행 중인 PowerPoint를 모두 강제 종료하던 것을, 같은 로그인 세션에서 창이 없는 것만 종료하도록 바꾼다. 강제 종료를 기다리는 시간에는 한도를 둔다.

이 셋은 기존 동작을 바꾼다. 기존 동작은 사용자가 PowerPoint로 작업 중인 내용을 저장 없이 잃게 할 수 있었다.

### D3. 가사 목록 글꼴은 단마다 하나를 함께 쓴다

미리보기 단과 송출 단이 각각 글꼴 하나를 갖는다. 글꼴 이름, 굵기, 미리보기 글자 크기가 바뀔 때만 새로 만든다. 이전 글꼴은 어떤 가사 칸도 쓰지 않을 때만 해제한다. 폼이 직접 만들지 않은 글꼴은 해제하지 않는다.

## Known Limitations

적대적 리뷰에서 나왔고 이번에 고치지 않는 것들이다.

- **쇼 도중 앱이 죽은 뒤**: 쇼가 열어 둔 PPT 복사본은 창이 있는 PowerPoint에 남는다. 다음에 앱을 시작해도 이 PowerPoint는 종료하지 않고(D2), 복사본이 남아 있는 동안에는 앱을 닫아도 PowerPoint가 끝나지 않는다. 사용자가 PowerPoint를 직접 닫아야 한다. 자료를 잃지는 않는다.
- **이름이 같은 새 문서**: 쇼용 복사본은 경로 없이 "프레젠테이션1" 같은 이름으로 열린다. 쇼 도중 PowerPoint가 다시 시작되고 사용자가 새 문서를 만들면 이름이 겹쳐, 쇼 종료 때 그 문서가 닫힐 수 있다. 드문 경우이고, 수정 전에는 모든 문서를 닫았다.
- **시작 직후 종료**: 백그라운드 초기화가 끝나기 전에 앱을 닫으면, 그 뒤에 만들어진 연결은 해제되지 않는다.
- **빈 PowerPoint**: 사용자가 PowerPoint를 문서 없이 열어 둔 경우 앱 종료 때 닫힌다. 잃는 자료는 없다.
- **앱은 시작할 때 항상 PowerPoint를 띄운다.** PPT 항목을 쓰지 않아도 그렇다. 미리보기 속도와 관련된 설계라 이번 범위에서 다루지 않는다.
- **응답하지 않는 PowerPoint**: 열린 프레젠테이션 수를 읽지 못하면 `Quit()`도 강제 종료도 하지 않는다. 사용자의 PowerPoint가 대화상자를 띄운 채 바쁜 경우와 구분할 수 없기 때문이다. 숨은 PowerPoint가 멈춰 있었다면 다음에 앱을 시작할 때 정리된다.
- **시작할 때의 정리 도중 프로세스가 사라지는 경우**: 확인하던 PowerPoint가 스스로 끝나면 예외가 나고 남은 프로세스는 정리하지 않는다. 다음 시작 때 다시 시도된다.
- **가사 글꼴 함수의 전제**: `GetLyricsFont`는 미리보기 단이 아니면 송출 단으로 본다. 지금은 두 단만 이 함수를 쓴다. 다른 패널에 쓰려면 먼저 고쳐야 한다.
- 폼이 만든 글꼴은 폼을 닫을 때 따로 해제하지 않는다. 프로세스가 바로 끝난다.
- `gfFileHelpers.ReleasePowerpointObjectsForCleanup`과 `gfFolder.DeleteFolderFiles`는 호출하는 곳이 없고, 조건 없이 PowerPoint를 끝낸다. 지우지 않고 둔다. 다시 연결하면 D2를 깨뜨린다.

## Verification

1. 빌드가 오류 없이 끝난다.
2. 수정 전 빌드와 수정 후 빌드로 "PPT 항목 미리보기 → 종료"를 실행해 종료 뒤 20초 동안 `POWERPNT.EXE`를 본다.
3. 가사 항목과 PPT 항목의 화면이 수정 전과 같다.

글꼴 수정의 효과는 GDI 객체 수로 잴 수 없다. 해제하지 않은 `Font`는 GDI 객체가 아니라 GDI+ 핸들과 관리 메모리를 쓰고, 종료자가 나중에 회수한다. 수정 전에도 GDI 객체 수는 늘지 않았다. 그래서 "목록을 다시 만들 때 새 글꼴을 만들지 않는다"를 기준으로 삼는다.
