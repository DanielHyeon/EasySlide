## Purpose

예배 송출 중 다른 창에 포커스가 있어도 설정된 단축키가 올바르게 동작하고, 일반 입력이 송출 UI의 응답성을 떨어뜨리지 않도록 한다.

## ADDED Requirements

### Requirement: 송출 단축키의 판정과 실행
시스템은 활성 명령과 보조키를 입력 시점에 판정해야 한다 (SHALL).

#### Scenario: Ctrl과 방향키
- **WHEN** Ctrl+방향키만 설정하고 Ctrl을 누른 상태에서 방향키를 뗀다
- **THEN** 다른 기능키의 구독 여부와 관계없이 해당 슬라이드 이동을 한 번 예약한다

#### Scenario: 활성 검은 화면 키
- **WHEN** WinForms에서 활성화한 F9 또는 F10을 누른다
- **THEN** 훅이 반환되기 전에 입력을 소비하고 화면 전환을 UI에서 실행한다

#### Scenario: 관련 없는 입력
- **WHEN** 활성 단축키 또는 미디어 키에 해당하지 않는 입력이 들어온다
- **THEN** UI에 작업을 등록하지 않고 입력을 전달한다

#### Scenario: WPF 전역 명령
- **WHEN** 실행 가능한 전역 단축키가 들어온다
- **THEN** 명령을 소비하고 UI 큐에서 실행하되 중지된 입력 세션의 명령은 실행하지 않는다

### Requirement: 네이티브 훅과 클릭 수명
공유 훅은 Windows의 포인터 크기와 해제 결과를 반영하고 완료된 클릭을 한 번 통지해야 한다 (SHALL).

#### Scenario: 해제 실패
- **WHEN** Windows가 유효한 훅의 해제에 실패한다
- **THEN** 오류 원인을 제공하고 같은 훅을 재시도할 수 있다

#### Scenario: 단일 클릭
- **WHEN** 왼쪽 또는 오른쪽 버튼을 한 번 누르고 뗀다
- **THEN** Down과 Up이 각각 한 번, Click과 ClickExt가 각각 한 번 발생한다
