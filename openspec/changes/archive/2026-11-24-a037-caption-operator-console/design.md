# Design — a037 카메라 자막 운영 창

## 현재 구조 (영향 근거)

- `CaptionConsole.xaml`(248줄)과 `CaptionConsole.xaml.cs`(약 880줄, a035·a036 이후 늘어남): 상태·조작 로직 대부분이 코드 숨김에 있다. `CaptionConsoleViewModel`은 초안·송출·숨김/표시만 가진다.
- 이름으로 컨트롤을 쓰는 곳: `Axicultus.Tests/Shell/CaptionConsoleTests.cs`(Draft, Instant, HideButton, ShowButton, Status 등), 접근성 테스트(이름 중복·레이블), `tools/AxicultusHarness/Program.cs` `pptcaption`(ScreenMode, DirectMode, TextOnly, ScoreOnly, ScoreAndText, SyncShow, LinesBox, ScoreSizeBox, SettingsToggle, ShowButton, HideButton, HiddenBadge, ScoreRowLabel, Slides, Boxes, Cue, ObsPreviewBox 등).
- 회중 창의 카메라 자막: `OutputWindow.xaml(.cs)`의 `CameraCaption`/`LowerThirdImage`/`LowerThirdArea`/`LowerThirdText`, `CaptionFit`.

## 결정

1. **창**: 같은 `CaptionConsole` 클래스를 다시 배치한다(열기 경로·수명·DI 그대로). `ResizeMode=CanResize`, 기본 1040×720, 최소 900×620. 닫기는 지금처럼 숨기기.
2. **창 위치 기억**: 프로필 폴더의 `caption-window.json`(Left, Top, Width, Height, Maximized). 화면 밖이면 무시하고 가운데. 읽기 실패는 무시.
3. **로직 이동(필요한 만큼만)**: 새 화면이 바인딩할 상태(현재 단계 표시, 다음 단계, 단계 목록, 송출 상태)는 뷰모델 속성으로 둔다. 이미 동작하는 PPT 준비·악보·OCR 로직은 옮기지 않아도 된다. 목표는 "새 XAML이 바인딩과 명령으로 동작"이지 전면 재작성이 아니다.
4. **미리보기 일치**: 회중 창 카메라 자막과 같은 배치 규칙(폭 88%, 자막 영역 줄 수, 글자 크기 = 높이의 5%, 악보 높이 비율, 배경 상자)을 16:9 미리보기에 비례로 적용한다. 권장 구현은 회중 창 카메라 자막 부분을 공유 UserControl로 떼어 두 곳에서 쓰는 것이다. 공유하면 회중 창의 결과 픽셀이 바뀌지 않아야 한다(하네스 그림으로 비교).
5. **다음 미리보기**: "다음 ▶"를 눌렀을 때 나갈 단계(같은 장 다음 줄 또는 다음 장)의 자막/악보 줄. 계산할 수 없으면 비운다. 송출은 하지 않는다.
6. **단계 띠**: 현재 따라가는 PPT의 단계 목록. 악보 단계는 줄 그림 썸네일, 자막 단계는 "N장" + 첫 줄. 누르면 자막만 그 단계로 간다(송출 화면은 움직이지 않는다). 현재 단계를 강조한다. 송출 화면 따라가기가 아니거나 PPT가 없으면 숨긴다.
7. **설정 창**: 모달 아닌 소유 창(`Owner=콘솔`). 지금 `SettingsPanel`과 `세부 조정` Expander의 컨트롤을 옮긴다. 콘솔의 설정 버튼이 연다.
8. **키보드**: 창 수준 `PreviewKeyDown`. 포커스가 TextBox/ComboBox/PasswordBox에 있거나 IME 조합 중이면 Space와 1~4는 처리하지 않는다. Esc 숨김과 ↑/↓·←/→ 단계는 기존 규칙(입력 칸 밖)을 따른다.
9. **테마**: 색·글꼴은 `DynamicResource Brush.*`, `Type.*` 스타일 등 기존 토큰. 새 XAML/코드에서 EasiDS001 경고가 나오지 않는다.
10. **이름 호환**: 테스트·하네스가 쓰는 컨트롤 이름은 가능하면 유지하고, 바꾸면 테스트와 하네스를 같은 변경에서 고친다. 자동화 이름(`AutomationProperties.Name`)은 모든 버튼·입력에 둔다.

11. **a036 동작 유지**: 상자 선택과 문구 고치기가 설정 창으로 옮겨가도 a036 규칙은 그대로다 — 운영자가 직접 고른 상자만 선택이 되고(`_chosenKey`/`Choose`), 고른 상자가 없는 슬라이드에서는 목록에 선택 표시가 없고, 저장하지 않은 문구 고치기는 송출 슬라이드가 바뀌거나 그림 속 가사 읽기가 끝나도 지워지지 않으며, 상자를 골라도 송출 중인 악보 줄과 보고 있는 슬라이드가 그대로다. a036의 콘솔 테스트는 모두 (이름만 바꿔) 통과해야 한다.
    - 단계 띠의 자막 단계 첫 줄과 다음 미리보기는 `TextFor(slide, 고른 상자)`를 쓴다(대체 규칙 포함). 표시 방식이 자동이면 슬라이드마다 a036 결정 7로 악보/자막을 정한다. 다음 미리보기는 지금 송출 중인 것이 악보 줄일 때만 같은 장 다음 줄이다(a036의 `_rowShown` 규칙과 같은 판단).
    - 1~4 키는 자동/자막/악보/악보+자막 순서다.
12. **화면 1개에서의 검증**: 하네스는 화면 2개가 있어야 돈다(가드를 풀지 않는다). 화면이 1개면:
    - 회중 창 카메라 자막의 변경 전후 비교는 테스트 안에서 한다. 공유 컨트롤로 바꾸기 **전에** 회중 창 카메라 자막 부분을 정해진 크기·자막·악보 줄·줄 수·악보 크기 조합으로 `RenderTargetBitmap`에 그린 기준 그림을 저장하고, 바꾼 뒤 같은 조합이 픽셀 단위로 같은지 비교하는 테스트를 둔다.
    - 총괄 화면 검사용으로, 임시 프로필에서 콘솔과 설정 창을 화면에 띄우지 않고 그린 그림(직접 입력, 따라가기-자막, 따라가기-악보, 숨김 시작, 송출 중, 설정 창, 최소 크기 900×620)을 작업 폴더에 남긴다. 실제 프로필과 실제 자료는 쓰지 않는다.

13. **숨김 중 미리보기**(구현 1차 질문 2): 숨김 중에도 미리보기는 "송출하면 나갈" 자막(직접 입력 글, 따라가는 단계의 자막·악보 줄)을 같은 배치로 그리고, 흐리게(불투명도 약 50%) 하며 "숨김 중 · 내보내지 않습니다" 표시를 유지한다. 콘솔 안에서만 그리는 것이며 세션의 송출(카메라 창, OBS 페이지)은 a023 규칙 그대로 아무것도 내보내지 않는다.
14. **작은 화면**(구현 1차 질문 6): 최소 크기와 처음 여는 크기는 창이 놓일 화면의 작업 영역을 넘지 않게 줄인다(예: 1024×768 125% → 약 819×614 DIP). 설계 최소(900×620)보다 작아지면 운영 창 본문이 잘리지 않고 스크롤된다. 송출/숨김 버튼이 있는 맨 위 줄은 스크롤되지 않고 항상 보인다.
15. **허용 한계**: 내용 그림이 없는(렌더 경로) 악보 슬라이드는 단계 띠에서 한 단계로 보이고, 렌더가 준비되기 전에는 다음 미리보기가 자막이다. 미리보기의 카메라 바탕은 영상 면이라 고정 검정색을 쓴다. 처음 쓸 때 OBS 설정 창이 저절로 열리지 않고, 맨 위 줄에 "OBS 연결 전 · 설정에서 연결하세요"를 보여 준다. 픽셀 기준 그림은 이 PC의 글꼴 렌더링으로 만들었다.

16. **송출 상태 세 가지**(리뷰 1차 2): 전환 버튼은 운영자의 송출/숨김 선택을 바꾸지만, 보여 주는 상태는 실제로 나가는지까지 따른다. (가) 숨김: 숨김 색·글자. (나) 송출 중이고 실제로 나감: 송출 색·글자. (다) 운영자는 송출을 골랐지만 회중 화면이 꺼짐(라이브 상태 Hidden/Standby)이라 a023 규칙대로 아무것도 나가지 않음: 주의 색과 "송출 대기 · 화면 꺼짐", 미리보기에는 "화면 꺼짐 · 내보내지 않습니다" 표시와 흐린 미리보기(결정 13과 같이). 세 상태 모두 밝은·어두운 테마에서 글자 대비 4.5:1 이상이어야 한다(리뷰 1차 1). 표시 배지도 같다.
17. **단계 띠와 PowerPoint 쇼 따라가기**(리뷰 1차 3): 따라가는 중 단계 띠·◀ ▶(싱크 끔)로 자막만 옮기면, 송출 화면(네이티브 쇼 포함)이 **다른 장으로 넘어갈 때까지** 자막은 고른 곳에 머문다. 쇼 확인(400ms 주기)은 쇼의 장이 마지막으로 본 장에서 바뀌었을 때만 자막을 옮긴다. a037 이전에도 ◀ ▶(싱크 끔)에 있던 결함을 같이 고친다.
    - "마지막으로 본 장"의 시작점: 따라가기를 시작할 때 화면 상태(켜짐·꺼짐·대기)와 상관없이 그때 쇼의 장을 기록한다. 아직 기록이 없으면 첫 확인은 기록만 하고 자막을 옮기지 않는다(리뷰 2차 1: 화면이 꺼진 동안 고른 단계가 화면이 돌아올 때 되돌아가지 않게).
    - 쇼를 끝냈다가 마지막에 보던 장에서 다시 시작하면 "넘어감"이 아니므로 자막은 고른 곳에 머문다(리뷰 2차 2).
    - 설정 창은 열 때마다 운영 창이 있는 화면의 작업 영역에 맞춘다(리뷰 2차 3).
18. **입력 칸 밖의 정의**(리뷰 1차 4·8): Space·1~4는 포커스가 TextBox/ComboBox/PasswordBox에 있거나 한글 조합 중이면 글자로 둔다. 추가로 (가) 1~4는 표시 방식 버튼이 보이는 "송출 화면 따라가기"일 때만 동작한다. (나) 직접 입력에서 "송출"·전환 버튼을 마우스로 누르면 포커스를 입력 칸으로 돌려 다음 글을 바로 쓸 수 있게 한다. (다) Esc는 설정 창에서도 자막을 숨긴다(콤보 목록이 펼쳐져 있으면 목록만 닫는다). (라) 싱크가 켜져 있으면 단계 키의 자동 반복은 무시한다.
    - (마) **포커스와 Space·화살표**(`/code-review` 1): 키보드(Tab)로 포커스를 옮긴 버튼·체크 상자·라디오·단계 띠 항목·목록에서는 Space와 화살표가 그 컨트롤의 기본 동작(누르기, 켜고 끄기, 선택 이동)이다. 마우스로 누른 운영 창의 버튼·체크 상자·라디오·단계 띠와 마우스로 펼쳐 고른 목록(자막 줄 수, 악보 크기)은 포커스를 남기지 않는다(리뷰 3차 1): 직접 입력이면 입력 칸으로, 따라가기면 운영 창 본문(포커스 표시 없는 창 자체, Tab 순서에는 넣지 않음)으로 돌린다. 그래서 마우스로 조작하는 운영자에게 Space는 늘 송출/숨김이고, 키보드로 컨트롤을 고른 운영자는 그 컨트롤을 쓴다.
19. **저장 안 한 문구는 어떤 이동에도 유지**(리뷰 1차 5, a037 이전부터): ◀ ▶·화살표·단계 띠·송출 화면 이동 어느 것도 설정 창의 저장하지 않은 문구를 덮어쓰지 않는다(a036 결정 4와 같은 규칙을 Step에도 적용).
20. **다음 미리보기 갱신**(리뷰 1차 6·12): 자막 모양(줄 수, 악보 크기, 글자색, 배경 상자)이 바뀌거나 다음 장의 악보 그림이 준비되면 다음 미리보기와 단계 띠를 다시 그린다. 미리보기와 단계 띠는 내용이 바뀔 때만 다시 그리고, 단계 띠는 현재 단계가 바뀔 때만 그 단계로 스크롤한다. 다음 미리보기의 악보 줄은 실제 송출과 같은 그림 출처(내용 그림 → 렌더 → 운영자 PowerPoint 미리보기 그림 순)로 계산한다(`/code-review` 7).
25. **따라가기로 돌아올 때**(`/code-review` 2): 직접 입력에서 "송출 화면 따라가기"로 돌아오면 자막은 송출 화면(출력 패널·쇼)이 지금 보여 주는 장을 따라간다. 설정 창의 슬라이드 선택값(오래됐을 수 있음)을 쓰지 않는다.
21. **창 위치 보정**(리뷰 1차 9·11, `/code-review` 3~6): 화면에 맞춰 크기를 줄일 때 위치도 작업 영역 안으로 옮긴다. 주 창이 최대화돼 있으면 주 창이 실제로 있는 모니터를 쓴다. 설정 창도 같은 규칙으로 작업 영역에 맞추고 스크롤한다(리뷰 1차 S4).
    - 배율이 다른 모니터에서 화면 사각형이 겹치지 않도록, 저장·복원과 화면 찾기는 **물리 픽셀**로 한다(구현: 보통 상태일 때의 `GetWindowRect` 화면 좌표를 저장하고, 보여 주기 전에 `SetWindowPos`로 놓은 뒤 최대화 상태를 적용 — 회중 창 배치 `DesktopWindowPlacement.Apply`와 같은 방식). WPF 단위로 각 모니터 원점을 그 모니터 배율로 나누는 방식은 쓰지 않는다. `caption-window.json`은 물리 픽셀 값과 최대화 여부를 저장하고, 이전 형식(WPF 단위) 파일은 기본 크기·주 창 화면 가운데로 연다.
    - 처음 열 때는 주 화면(`Screen.PrimaryScreen`)이나 주 창이 있는 화면을 쓴다. 진짜 화면을 알기 전에 크기를 줄여 두지 않는다.
    - 운영 창과 설정 창은 보여 줄 때마다 화면 목록을 다시 읽는다(모니터를 떼고 붙인 경우). 최대화·최소화 상태로 숨긴 운영 창도 다시 열 때 저장된 보통 위치가 화면 밖이면 작업 영역 안으로 옮긴 뒤 상태를 적용한다(리뷰 3차 2). 하네스도 실제 앱과 같은 열기 경로(`ShowOnScreen`)를 쓴다. 설정 창은 열 때마다 운영 창이 있는 화면에 맞춘다.
    - 최대화한 뒤 최소화한 상태로 닫아도 최대화 여부를 기억한다.
22. **좁은 맨 위 줄**(리뷰 1차 10): 폭이 모자라면 "내보낼 곳" 글을 먼저 빼고, OBS 상태는 두 줄까지 줄바꿈해 읽을 수 있게 둔다(말줄임만 남기지 않는다).
23. **미리보기 겹침**: "카메라 미리보기는 설정에서 켭니다" 안내는 자막·악보 줄보다 뒤에 그리고, 자막·악보 줄(흐린 미리보기 포함)이 있는 동안 비친다면 숨긴다.
24. **접근성**: 단계 띠 항목은 "N장" 또는 "N장 M줄"과 첫 줄을 읽히는 자동화 이름을 가진다.
- 허용 한계(리뷰 1차 13): 인터페이스 크기 "작게"에서는 본문 글자가 15px보다 작을 수 있다(운영자가 고른 크기).

## 위험과 대응

- 코드 숨김 결합: 단계적으로 옮기고 매 단계 전체 테스트.
- 회중 창 회귀: 공유 컨트롤로 바꾸면 하네스의 `caption-*`/`score-size-*` 그림을 변경 전후로 비교한다.
- 접근성 테스트: 레이블 중복과 이름 없는 입력을 그대로 검사한다.
