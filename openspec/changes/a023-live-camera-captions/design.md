# 설계

## Context

WPF의 MainViewModel은 준비 중인 항목과 송출 항목을 구분한다. LiveSessionService가 확정한 화면을 콘솔과 출력 창이 구독한다. 이 설계는 기존 예배 순서, DirectShow 백엔드, PowerPoint 슬라이드 쇼, 모니터 선택·배치 기능 위에 카메라 하단 자막을 추가한다.

## Goals / Non-Goals

예배당 프로젝터와 온라인 카메라 방송에 서로 다른 배경을 유지하면서 같은 자막을 사용할 수 있게 한다. 운영자가 선택한 문구만 공개한다. PPT의 이미지 속 글씨는 운영자가 입력할 수 있도록 한다. 네이티브 PPT 쇼의 애니메이션과 기존 송출 단축키는 계속 사용할 수 있어야 한다.

## Decisions

1. 콘솔의 편집 초안과 확정 자막을 분리한다. WPF Dispatcher에서 상태를 직렬화하고 외부 출력에는 순번과 최종 텍스트만 노출한다. 한글 조합 도중 전송을 보류한다. 직접 입력하면 PPT 따라가기를 중지한다. 숨김은 내용을 보존한다.
2. PPT 파일 준비는 배경에서 수행한다. 파일에 기록된 슬라이드 순서와 텍스트 상자 단위를 보존한다. 같은 자리표시자나 이름의 상자를 다음 장에서 찾고, 부재 시 빈 자막을 보낸다. 미리보기 선택으로 Live를 변경하지 않는다. 자막 전용 다음 장 버튼은 PowerPoint 쇼를 시작하지 않는다.
3. OBS Browser Source는 루프백 읽기 전용 오버레이다. 새 접속은 최신 상태를 받고 연결 상실 시 자막을 지운 뒤 재접속한다. OBS v5 제어는 별도 연결로 인증하고 OBS에서 보고된 프로그램 씬을 따른다. 방송 카메라 점유는 OBS에 맡기고 프로젝터용 로컬 카메라를 명시적으로 선택할 수 있다.
4. 기존 예배 순서 JSON과 레거시 .esw 및 곡 DB를 유지한다. 예배별 복구본은 별도 경로에 초안·선택·슬라이드 수정과 이력을 기록한다. 저장은 고유 임시 파일과 이전 정상본으로 교체한다. 복구는 편집 상태만 복원한다.
5. 수집 스레드와 UI가 서로 다른 프레임 버퍼를 소유한다. 종료 및 장치 손실에서 콜백을 분리하고 재연결 시 그래프를 다시 생성한다. 출력 위치는 물리 픽셀 배치를 재사용하고 화면 구성 변경을 합쳐 처리한다.
6. 정적 슬라이드 변환은 별도 프로세스에 넣고 기존 이미지 바이트 LRU를 재사용한다. 호스트는 취소·타임아웃 결과를 구분하고 소유한 워커만 중단한다. 로컬 송출과 외부 송출 장애를 분리한다.

## 예배 운영 순서

1. **예배당에는 전체 PPT, 온라인에는 카메라와 가사**를 보낼 때는 기존 방식으로 회중 모니터에 PPT를 송출한다. WPF 메인 화면에서 **Output → 카메라 하단 자막…**을 열어 **카메라는 OBS에서 사용**을 켜고 **회중 화면에도 자막 표시**를 끈다. OBS 씬에 카메라를 두고 그 위에 브라우저 소스를 배치한다. 브라우저 소스 크기는 OBS 기본 캔버스에 맞춘다.
2. **OBS** 탭에서 **자막 서버 시작**을 누른다. 브라우저 소스 주소는 `http://127.0.0.1:17948/`이다. 같은 PC에서 사용할 수 있다. 이 단계만으로 확정 문구를 방송에 합성할 수 있다. EasiSlides에서 씬도 제어하려면 OBS의 WebSocket 서버를 켜고 포트와 암호를 입력해 연결한다.
3. **PPT 자막** 탭의 **현재 송출 PPT** 또는 **PPT 열기…**에서 문서를 준비한다. 장과 텍스트 상자를 고른 다음 **PPT 따라가기**를 누른다. 같은 자리표시자나 같은 이름의 텍스트 상자가 있는 장으로 이동하면 문구가 바뀐다. 그림 악보는 해당 장에 수동 문구를 저장한다. 별도의 PPT 쇼 없이 카메라만 방송할 때는 **이전 자막 / 다음 자막**으로 진행한다.
4. **직접 입력** 탭에 설교 요점이나 안내를 적고 **Ctrl+Enter**를 누르면 직접 입력 모드로 전환된다. **실시간 반영**은 선택한 후 확정된 입력부터 반영한다. 자막 창에서 **Esc** 또는 **자막 숨김**을 누르면 카메라를 유지하고 문구를 숨긴다. **다시 표시**는 마지막 문구를 복원한다.
5. 로컬 카메라를 회중 창에 보낼 때는 콘솔에서 **로컬 카메라 켜기 / 끄기**와 **회중 화면에도 자막 표시**를 사용한다. OBS가 카메라를 점유하는 구성에서는 **OBS 카메라 미리보기**에 해당 OBS 비디오 소스 이름을 지정한다. 미리보기용 카메라를 따로 열 필요가 없다.

## 상태와 스레드

| 처리 주체 | 소유 상태와 동작 | 실패 시 동작 |
|---|---|---|
| WPF Dispatcher | 초안, 선택한 장·상자, 따라가기 모드, 표시 여부, 확정 문구를 갱신한다. 버튼·IME·슬라이드 통지의 순서를 유지한다. | 파일 읽기와 OBS 응답을 비동기로 기다린다. 늦게 도착한 이전 문서·연결·슬라이드의 결과를 버린다. |
| 로컬 카메라 워커 | DirectShow 장치와 그래프를 전담한다. 쓰기·대기·읽기 버퍼 세 개를 교환하고 UI는 약 33ms마다 최신 완성 프레임을 그린다. | 장치를 잃으면 그래프와 콜백을 해제하고 같은 장치 경로를 다시 찾는다. 대기 상태를 표시한다. |
| OBS 제어 | 포트 기본값은 4455이다. 인증 후 실제 프로그램 씬과 목록을 읽고 외부 변경 통지를 반영한다. 선택한 씬에서 소스 표시를 먼저 바꾸고 씬을 전환한다. | 중단 시 1·2·4·5초 간격으로 재시도한다. 인증 거부·세션 강제 해제는 운영자가 다시 연결한다. 부분 성공은 경고하고 이전 명령을 재생하지 않는다. |
| 브라우저 소스 | 투명한 HTML 위에 확정 문구를 텍스트로 표시한다. 각 연결은 최신 상태 한 건을 대기시킨다. | 연결 상실 시 자막을 비우고 1초 간격으로 재접속한다. 첫 응답으로 현재 상태를 복원한다. |
| PowerPoint 변환 | 같은 실행 파일을 별도 워커 모드로 시작해 읽기 전용 복사본에서 PNG 또는 구형 문서 텍스트를 추출한다. 요청 크기, 장 번호 및 파일 변경 정보가 이미지 캐시 키에 포함된다. | 시간 초과 시 해당 워커를 중단한다. 네이티브 슬라이드 쇼, 다른 사용자가 연 문서, OBS를 일괄 종료하지 않는다. |

OBS 씬과 소스 제어는 순차 배치로 처리한다. 두 번째 요청이 실패하면 이미 적용된 첫 번째 요청은 유지될 수 있다. 콘솔에는 OBS가 마지막으로 보고한 씬을 표시한다. [OBS WebSocket v5 프로토콜의 RequestBatch](https://github.com/obsproject/obs-websocket/blob/master/docs/generated/protocol.md#requestbatch-opcode-8)

프로덕션 이미지 디코더는 백그라운드에서 비트맵을 만들고 Freeze한 뒤 UI에 넘긴다. 먼저 메모리 LRU를 조회하고, 필요하면 설정 폴더의 `Cache/PowerPoint`에서 PNG를 읽는다. 디스크 캐시는 최대 512개, 용량은 설정된 썸네일 캐시 한도를 따른다. 파일 수정 시각·크기 또는 렌더 해상도가 달라지면 새로 변환한다. 체크섬 오류가 있는 항목도 다시 변환한다. 텍스트 상자만 준비하는 경우 PNG 변환을 생략한다.

## 저장 및 장애 복구

| 데이터 | 저장 위치와 복구 기준 |
|---|---|
| 예배 순서와 찬양 가사 | 기존 예배 순서 저장소와 곡 DB를 사용한다. 복구본에는 순서가 있는 WorshipListItemDto 배열, 가사, 곡의 절·후렴 순서, 개별 서식과 선택 위치를 함께 보관한다. 같은 곡이 반복되면 목록 위치로 복구한다. |
| 설교 초안·PPT 자막 | 설정 파일 옆 `CaptionRecovery`에 예배 이름별 JSON을 저장한다. 버전, 순번, 초안, PPT 경로·장·상자, 장별 보정 문구, 최근 확정 이력 최대 100건을 보관한다. 이름이 없는 예배는 공통 임시 작업으로 취급한다. |
| 복구 동작 | 변경을 600ms 동안 모아 고유 임시 파일에 쓰고 디스크에 플러시한 뒤 교체한다. 읽을 수 있는 직전 파일을 백업으로 유지한다. 운영자가 **예배 편집 복구…**를 확인하면 편집 내용만 복원한다. 손상되거나 이동한 PPT는 다시 지정할 수 있다. |
| OBS 제어 프로필 | 설정 파일 옆 `obs.json`에 포트와 씬 이름을 저장한다. **앱 시작 시 자동 연결 및 자막 서버 시작**을 선택하면 Windows 현재 사용자 자격으로 암호를 보호해 저장한다. 4개 씬은 운영자 창에서 **Ctrl+Alt+1~4**로 호출한다. 등록한 씬이 없는 키는 기존 키 처리로 전달한다. |

## 배포와 인수시험

- 프레임워크 종속 배포에는 대상 아키텍처의 .NET 11 Windows Desktop 런타임과 ASP.NET Core 11 공유 런타임이 필요하다. PPTX 계열의 텍스트 상자 추출에는 Office 설치가 필요하지 않다. 구형 PPT/PPS 텍스트와 PowerPoint 원본 렌더링에는 데스크톱 PowerPoint가 필요하다.
- 회귀시험은 임시 설정 경로와 프로세스별 HKCU 테스트 키를 사용한다. 한글 조합 중 미송출, PPT 자체 장 전환 후 수동 입력 우선, 브라우저 재접속·암전, 손상된 최신본의 복구, 한 장치 점유 및 최신 프레임, OBS 인증·부분 실패·재접속을 확인한다.
- 현장에서는 100%와 150% 배율의 디스플레이 조합에서 4:3·16:9 전체 PPT와 온라인 하단 자막을 동시에 확인한다. HDMI 분리·재연결 뒤 선호 모니터와 입력 포커스가 복원되는지 확인한다.
- USB 카메라를 빼고 같은 포트에 연결해 영상 복구를 확인한다. OBS를 재시작해 카메라 위에 최신 문구가 한 번만 나타나는지 확인한다. 4시간 리허설 중 프로세스 메모리·핸들 수·영상 지연을 시작과 종료 시점에 기록한다.

## Risks / Trade-offs

그림으로 만들어진 악보는 수동 문구가 필요하다. 자막 바 숨김은 온라인 카메라 영상의 암전과 구분한다. 네이티브 PowerPoint 슬라이드 쇼를 온라인으로 캡처할 경우 OBS에서 투명 자막 소스를 별도 합성한다. 실물 카메라, 혼합 DPI, 장시간 송출은 현장 인수시험으로 판정한다.
