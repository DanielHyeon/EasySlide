# Design: 쇼 진행 중에 PowerPoint가 멈춰도 앱이 멈추지 않게 한다

## 확인된 것 (2026-11-17)

- 쇼 끝과 앱 닫기의 호출은 `fix-ppt-show-end-timeout`이 제한한다 (`PowerPoint.ProbePowerPoint`, `PowerPointCallLimit`, 놓지 못한 참조의 보관).
- 쇼 진행 중의 호출 (앞 변경의 조사):
  - 미리 열기: `gfFileHelpers.PreLoadPowerpointFiles` (`NewApp`, `EnsureAttached`, `Open`, `Activate`, 창 상태). 쇼 시작과 쇼 도중의 목록 변경에서 부른다.
  - 항목 불러오기: `Gf.RunPowerpointSong` (`Run`, `First` / `GotoSlide` / `Count`, `SetShowWindow`, `LoadVersesAndSlides`). 송출 창(`LivePP`)과 메인 화면(`MainPPT`)이 각각 부른다. `AdoptLivePowerpointRun`, `FollowRunOf`.
  - 슬라이드 넘김: `ImplementPowerpointSlideMovement`, `SafePlayNext`, `ReprobeEndedLivePowerPoint` (`RefreshRunShowState`).
  - 창 다루기: `MinimizePowerPointWindows` 등.
  - 메인 화면의 PPT 항목 불러오기: `OutputPPT`의 `IsBuildedFileCheck`, `LoadVerses`, `BuildScreenOutDumps` (슬라이드 이미지 내보내기).
- 시작하지 못한 PPT 항목과 끝난 PPT 항목에는 이미 규칙이 있다: 송출 창이 투명하지 않게 되고 기본 배경을 그린다 (`LivePowerPointNotStarted`, `LivePowerPointEnded`, `FrmLaunchShow.ShowSlide`). 상태 줄에 표시하고 알림을 한 번 낸다.
- PowerPoint를 새로 띄우는 호출과 큰 파일을 여는 호출은 정상일 때도 몇 초가 걸린다.

## Decisions

### P1. 하나의 관문

쇼 시작부터 쇼 끝까지 메인 화면 스레드에서 PowerPoint로 가는 호출 묶음은 모두 하나의 관문을 지난다. 관문이 하는 일:

1. "응답 없음" 상태이면 P3의 규칙으로 건너뛸지 정한다.
2. 무거운 묶음이면 먼저 응답을 확인한다 (P2).
3. `PowerPointCallLimit` 아래에서 호출한다. 포기되면 P3로 간다.

관문을 어디에 둘지(호출하는 쪽의 묶음 단위, 또는 래퍼의 공개 메서드)는 구현에서 정한다. 조건: 빠진 호출이 없을 것 (직접 `prePowerPointApp`을 부르는 곳 포함), 겹쳐 불려도 한 묶음으로 동작할 것 (`Begin`이 이미 그렇게 한다), 쇼 끝과 앱 닫기의 기존 동작을 바꾸지 않을 것.

쇼가 꺼져 있을 때의 미리보기 썸네일 만들기(`PreviewPPT`)도 같은 관문을 쓸 수 있으면 쓴다. 따로 손이 많이 가면 이번에는 넣지 않고 기록한다.

### P2. 정상인 PowerPoint를 끊지 않는다

잘못 끊으면 예배 중에 PPT 항목이 안 나온다. 그래서 제한은 느슨한 쪽으로 둔다.

- **가벼운 묶음** (슬라이드 넘김, 수 읽기, 상태 묻기, 창 옮기기): 평소에는 확인 없이 부른다. 한 호출도 끝나지 않은 채 5초가 지나면 포기한다. PowerPoint가 5초 안에 답하면 이전과 똑같이 동작한다.
- **무거운 묶음** (미리 열기, 슬라이드 쇼 실행, 슬라이드 이미지 내보내기): 부르기 전에 응답을 확인한다 (2초). 응답하면 부르고, 묶음 안의 진행 없는 시간 제한은 30초로 둔다 (큰 파일 열기). 각 파일, 각 슬라이드가 끝날 때마다 진행으로 친다.
- **PowerPoint가 떠 있지 않을 때** (새로 띄우는 경우): 멈춘 프로세스가 없으므로 확인할 것이 없다. 띄우는 호출의 제한은 60초로 둔다.
- 전체 상한(30초)은 무거운 묶음에는 맞지 않는다. 묶음별로 정한다 (미리 열기는 파일 수에 비례).

숫자는 구현에서 재 보고 조정할 수 있다. 조정했으면 이유를 적는다.

### P3. "응답 없음" 상태

- 확인이 실패하거나 묶음이 포기되면 "응답 없음" 상태가 된다. 래퍼들은 쥐고 있던 참조를 놓지 않고 보관하며 (앞 변경의 방식), 기억하던 실행을 잊는다.
- 쇼 복사본 목록(`PowerpointList`)은 그대로 둔다. PowerPoint가 다시 응답하면 그 복사본들은 열린 채로 있으므로 다시 붙어서 쓴다. (목록을 옮기는 것은 쇼 끝에서만 한다.)
- 이 상태에서 PowerPoint 호출 묶음이 요청되면: 마지막 확인으로부터 2초가 지났을 때만 짧게(0.3초) 다시 확인한다. 응답하면 상태를 풀고 진행한다. 아니면 기다리지 않고 건너뛴다. 건너뛴 묶음은 "PowerPoint에 닿지 못했다"는 기존의 실패 결과를 돌려준다 (슬라이드 수 0, 시작 안 됨 등).
- 상태가 바뀔 때마다 기록한다. 알림은 상태에 들어갈 때 한 번 ("PowerPoint is not responding: PowerPoint items cannot be shown until it answers again"는 뜻의 문구), 풀릴 때 한 번 낸다.
- 쇼 끝과 앱 닫기는 앞 변경대로 동작한다 (자체 확인과 재시도). 이 상태를 참고하되 규칙을 바꾸지 않는다.

### P4. 화면

- **응답 없음 상태에서 PPT 항목을 불러올 때** (또는 불러오는 중에 포기될 때): "시작하지 못한 PPT 항목"의 기존 규칙. 송출 창은 불투명해지고 기본 배경을 그린다. 그 아래의 멈춘 슬라이드는 가려진다. 상태 줄의 표시와 알림도 기존 규칙대로.
- **이미 송출 중인 PPT 항목에서 슬라이드를 넘기려 할 때**: 화면을 바꾸지 않는다 (청중이 보고 있는 슬라이드 그대로). 넘김은 일어나지 않고 알림이 나온다. 일시적으로 바쁜 PowerPoint 때문에 화면이 기본 배경으로 바뀌는 일을 피한다.
- **가사, 성경, 이미지 항목**: 평소와 같다. 송출 창이 불투명하므로 멈춘 슬라이드를 가린다. 이 항목들을 불러올 때 PowerPoint 창을 내리는 호출이 있으면 그것도 관문을 지난다 (건너뛰어도 송출에는 지장이 없어야 한다).
- **다시 응답한 뒤**: PPT 항목을 다시 불러오면(다른 항목으로 갔다가 돌아오거나 같은 항목을 다시 선택) 정상으로 송출된다. 송출 중이던 항목의 슬라이드 쇼가 살아 있으면 다음 넘김부터 다시 동작한다. 자동으로 항목을 다시 불러오지는 않는다.
- 메인 화면: 썸네일을 만들지 못한 PPT 항목은 기존의 실패 표시를 따른다.

### P5. 쇼 시작

`fix-ppt-show-end-timeout`의 재시도 뒤에 미리 열기가 온다. 미리 열기는 무거운 묶음이다. 응답이 없으면 건너뛰고, 쇼는 시작된다 (PPT 항목은 P4대로). 쇼 도중에 PowerPoint가 다시 응답하면, PPT 항목을 불러올 때 필요한 파일을 그때 연다 (이미 있는 "쇼 도중의 미리 열기" 경로를 쓸 수 있는지 확인한다. 없으면 그 항목만 연다).

## 시험 방법

앞 변경과 같다: 시험 인스턴스가 이번 실행에서 띄운 POWERPNT만 멈췄다가 푼다. 이미 떠 있던 PowerPoint가 있으면 하지 않는다. 예배 목록에는 입력을 보내지 않는다 (`btnToOutput`, `OutputBtnItemDown/Up`, `OutputBtnSlideDown/Up`, `cbGoLive`만).

1. PPT 항목 송출 중에 멈춤 → 슬라이드 넘김: 5초 안에 돌아오고 알림, 화면 그대로. 다시 넘김: 바로 돌아온다.
2. 그 상태에서 다음 항목(가사)으로: 평소처럼 송출되고 멈춘 슬라이드가 가려진다.
3. 그 상태에서 PPT 항목으로: 기본 배경, 알림, 앱 응답.
4. 재개 → PPT 항목을 다시 불러옴: 정상 송출, 슬라이드 넘김 동작.
5. 멈춘 채 쇼 끄기 → 쇼 다시 켜기 (앞 변경의 한계였던 경우): 쇼가 시작되고 앱이 응답한다. 가사 항목 송출. 재개 뒤 PPT 항목 송출.
6. 정상 경로: 쇼 시작, 항목 이동, 슬라이드 넘김, 쇼 끄기의 시간과 출력 모니터 화면이 수정 전과 같다. PowerPoint가 떠 있지 않은 상태에서의 첫 쇼 시작 포함.
7. 느리지만 정상인 경우 (임시 지연 스위치): 끊기지 않는다.

## 구현하면서 정한 것 (2026-11-17)

- **관문의 자리** (`OfficeLib/PowerPointGate.cs`): PowerPoint를 부르는 래퍼의 공개 메서드가 스스로 관문에 들어간다. 그래서 호출하는 쪽에서 빠뜨릴 수 없다. 여러 호출이 한 가지 일인 곳은 바깥에서 한 번 들어간다: 미리 열기(`PreLoadPowerpointFiles`, 직접 호출 포함)와 항목 불러오기(`RunPowerpointSong` 전체). 안쪽의 호출은 바깥 묶음에 속한다. 쇼 끝과 앱 닫기의 묶음(`fix-ppt-show-end-timeout`)은 그대로이고, 그 안의 래퍼 호출은 그 묶음에 속한다.
- **메인 화면 스레드에서만 적용한다.** 앱 시작 때 백그라운드 스레드에서 PowerPoint에 붙는 `Init`은 확인도 제한도 없이 지나간다 (그 스레드는 기다려도 해가 없다). 관문의 상태는 메인 화면 스레드만 쓴다.
- **숫자**: 가벼운 묶음은 진행 없는 시간 5초. 무거운 묶음은 확인 2초 뒤 진행 없는 시간 30초, 전체 상한은 사실상 없음(30분: 슬라이드가 많은 파일의 이미지 만들기를 끊지 않는다). PowerPoint 프로세스가 없으면 확인 없이 60초. 직전 묶음이 끝난 지 1초 안이면 무거운 묶음도 확인을 건너뛴다. 응답 없음 상태에서는 2초에 한 번만 0.3초 동안 다시 확인한다.
  - 정상일 때 잰 값: 미리 열기(9개) 3.7~5.0초, 슬라이드 이미지 0.4~1.0초, 슬라이드 쇼 실행 0.1~0.5초, 넘김 10~115ms, 확인 12~18ms.
- **P3와 다르게 한 것**: 응답 없음 상태가 되어도 래퍼의 참조를 버리지 않고 기억한 실행도 잊지 않는다. 포기된 묶음 안에서 놓으려던 것만 보관한다. 이유: PowerPoint가 풀린 뒤 송출 중이던 항목의 넘김이 그대로 다시 동작해야 한다(P4). 취소된 뒤에도 참조는 계속 쓸 수 있었다. 예외: 항목 불러오기가 슬라이드 쇼를 시작한 뒤에 포기되면 그 실행은 잊고 "시작하지 못함"으로 처리한다 (반쯤 시작된 상태를 남기지 않는다).
- **포기된 묶음이 열어 둔 임시 프레젠테이션**(절 정보 읽기, 이미지 만들기)은 "나중에 닫을 것"으로 기억했다가 PowerPoint가 다시 응답할 때 닫는다. 열기 호출 자체가 취소되어 참조를 받지 못한 경우는, 파일 경로로 연 것(이미지 만들기)만 경로를 기억해 두고, 그 이름의 프레젠테이션에 창이 없을 때만 닫는다.
- **슬라이드 쇼 창 내리기**(`LowerWindow`): 창이 0.3초 안에 답하지 않으면 기다리지 않는 방식(`SWP_ASYNCWINDOWPOS`)으로 보내고 목록에 남긴다. 관문의 상태에는 묶지 않는다 (가사 항목만 이어질 때는 관문을 지나지 않아 상태가 풀리지 않는다).
- **미리 열기를 건너뛴 경우**(P5): `Gf.PowerPointPreloadPending`을 세우고, 다음 PPT 항목을 불러올 때 기존의 "쇼 도중 미리 열기"를 먼저 실행한다. 포기되거나 건너뛴 열기는 파일의 실패로 세지 않는다.
- **쇼 끝 쪽과 상태를 나눈다**: 쇼 끝과 쇼 시작의 재시도가 "응답 없음"을 보면 관문의 상태도 세운다. 이어지는 미리 열기는 다시 확인하지 않고 바로 건너뛴다.
- **알림**: 상태에 들어갈 때 "PowerPoint is not responding: PowerPoint items cannot be shown until it answers again", 풀릴 때 "PowerPoint answers again: load a PowerPoint item again to show it". 넘김이 건너뛰어지면 항목마다 한 번 "The PowerPoint slide could not be moved: PowerPoint is not responding". 풀림의 알림도 알림 칸(오류 표시)에 나온다.

## Known Limitations

- **멈춘 동안 "다음"은 항목을 넘기지 않는다.** 송출 중인 PPT 항목에서 PowerPoint가 응답하지 않으면 슬라이드 넘김은 아무 일도 하지 않는다. 다른 항목으로 가려면 항목을 직접 선택해야 한다 (리모컨만 쓰는 경우 포함).
- **자동으로 다시 불러오지 않는다.** PowerPoint가 다시 응답해도, 기본 배경으로 바뀐 PPT 항목은 다시 불러와야 보인다.
- **확인을 통과한 직후에 멈추면 오래 걸린다.** 무거운 묶음(항목 불러오기, 미리 열기, 이미지 만들기) 안에서 멈추면 30초 뒤에 포기한다. 큰 파일을 끊지 않기 위한 값이다.
- **정상이지만 잠깐 바쁜 PowerPoint**: 무거운 묶음 앞의 확인(2초)에 답하지 못하면 그 PPT 항목은 "시작하지 못함"이 된다. 다시 불러오면 된다.
- 미리 열기 도중 취소된 "쇼 복사본 열기"가 PowerPoint 안에서 끝나 버리면, 그 복사본은 이름도 표식도 없어 앱이 닫을 수 없다. 이름 없이 연 임시 프레젠테이션(슬라이드 수, 절 정보)의 취소된 열기도 같다.
- 쇼 끝에서 닫지 못한 이전 쇼의 복사본은 다음 쇼 시작의 재시도가 실패하면 앱 닫기까지 열려 있다 (맨 위에서는 내려가 있다).
- 확인과 참조 해제 사이에 멈추는 경우는 앞 변경과 같이 남는다.

## 확인하지 못한 것 (코드로만 확인)

- 앱 시작 중에 PowerPoint가 응답하지 않는 경우, Windows 세션 종료 중의 앱 닫기
- 경로로 연 임시 프레젠테이션의 열기가 취소된 뒤의 복구
- 쇼가 꺼져 있을 때의 미리보기 썸네일 만들기 도중의 멈춤 (같은 관문을 지난다)
- 라이브 카메라 항목, 단일 모니터의 모달 쇼
- 느린 열기·실행·넘김을 일부러 만든 시험은 리뷰 수정 전 빌드에서만 했다 (그 뒤 가벼운 묶음의 코드는 바뀌지 않았다)
