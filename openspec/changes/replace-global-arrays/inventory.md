## 정적 배열 필드 밖의 저장소

- 전역 `SongSettings` 10개의 슬라이드·구절 버퍼를 가변 크기로 변경했다. 두 표 모두 처음에는 0번과 1번 행만 갖는다. 가사는 행이 찰 때 용량을 두 배로 늘리고, PowerPoint는 프레젠테이션이나 이미지·구절 캐시에서 확인한 마지막 장까지 확보한다. 구절별 줄 범위는 곡에 등장하는 가장 높은 구절 번호에 맞춰 확보하고, 영역별 첫 줄과 끝 줄을 한 번의 순회로 기록한다. 확보한 용량은 같은 객체에서 다음 곡을 열 때 재사용한다.
- 열 개 객체에서 두 표의 초기 정수 데이터가 **352,320 → 1,040바이트**로 줄었다. Windows x64의 .NET 11 Release에서 예열 후 `SongSettingsBase` 10개 생성을 100회 반복해 측정한 전체 관리 힙 할당량은 10개당 **390,960 → 39,680바이트**였다.
- 회귀 테스트로 같은 객체에서 가사 1 → 1,000 → 1,001 → 3장 전환, 두 번째 영역에만 남는 페이지, 높은 구절 번호 재사용, PowerPoint 1,000·1,001번째 표식과 캐시 무효화를 확인했다. 설치된 PowerPoint로 임시 3장 PPTX를 만들고 OfficeLib의 이미지 내보내기를 실행했다. 첫 장의 2절, 표식 없는 두 번째 장, 마지막 장의 엔딩 표식이 이미지 내보내기와 캐시 재조회에서 모두 일치했다.
- 각 곡의 `LoadIndividualFormatData`는 헤더를 항목 순서대로 한 번 읽어 기존 `SongFormat.HeaderData`의 255개 슬롯을 채운다. 중복 키는 첫 값이 비어 있어도 그 값을 유지하고, 끝에 `>`가 없는 항목은 무시한다. 같은 곡 객체를 재사용할 때 이전 값도 지운다.
- 회귀 테스트는 기존 단일 키 조회와 255개 슬롯을 비교하고 글꼴·배경·미디어·이조 설정에 반영된 값도 확인한다. 별도 대조에서는 한국어·영어·일본어·아랍어·태국어 설정별로 생성한 헤더 75개씩, 총 95,625개 슬롯이 기존 조회 결과와 일치했다.
- WPF의 명령, 파일 복사 목적지, 전환 효과, 추천 글꼴에는 `IReadOnlyList<T>`로 선언한 정적 목록도 있다. 전환 효과와 추천 글꼴은 다른 필드에서도 같은 목록을 참조한다. 참조 수와 실제 할당 수는 구분해 집계했다.

### 가사 편집기의 화면 나눔

곡 편집과 안내 화면 편집이 공유하는 `MapLyricsBreak`에서 `[메모]`를 만난 회귀 테스트가 수정 전에는 15초 안에 끝나지 않았다. `ValidateVerseIndicator`는 빈 슬롯 104번에서 비교를 마쳐 111·112번 프리코러스 표식을 놓쳤다.

이제 화면 나눔은 편집기의 텍스트를 한 번 가져와 앞으로 이동하고, 대괄호 안의 표식을 기존 구절 조회표에서 찾는다. 미등록 표식, 닫히지 않은 대괄호, 영역 전환 기호는 구절 번호를 바꾸지 않는다. WinForms 컨트롤을 사용하는 테스트로 두 프리코러스, 같은 구절의 연속 화면 번호, 첫 글자 뒤 빈 줄, 두 언어 영역의 다음 화면 위치가 맞는지 검증했다.

### 슬라이드 미리보기 본문과 코드 정렬

미리보기 본문은 해당 영역의 행을 한 번 읽는다. 코드 표시가 꺼져 있으면 완성된 본문의 대시 표식을 한 번에 처리한다. 영역에 행이 없음을 뜻하는 `-1`은 기존 호출자가 기대하는 빈 줄로 반환한다. 코드가 있는 행은 슬라이드 안의 상대 행 번호를 유지한다.

문서와 HTML에서 쓰는 코드 정렬은 실제 글꼴로 공백 너비를 추정한 뒤, 기존 픽셀 목표에 처음 도달하는 공백 수를 측정해 결정한다. 프린터의 공백 보정과 화면용 코드 사이 간격을 각각 검증했다. 내보낼 줄을 나눌 때 측정용 `Graphics`를 행 사이에 재사용하고 호출이 끝나면 해제한다. 열 너비가 공백보다 좁아 다음 줄로 진행하지 못하던 입력도 회귀 테스트에 포함했다.

### 괄호 코드 보존과 편집기 부분 서식 갱신

저장된 `(0;C(add9);0;G/B;08;)`를 두 반음 올리면 `(0;D(add9);0;A/C#;08;)`가 된다. WinForms와 WPF는 같은 규칙으로 코드 접미사 안의 괄호와 슬래시를 판독한다. 이조 메뉴의 올림·내림, 다음 코드와 행 번호, 중첩 괄호, WPF 곡 병합 시의 위치 보존을 회귀 테스트로 확인했다.

WinForms는 가사 영역별로 직전에 서식을 적용한 본문을 보관한다. 편집한 본문과 비교해 달라진 줄의 글꼴과 색상을 한 번에 적용하고 선택 영역을 복원한다. 실제 두 편집기의 여러 줄 삽입 이벤트와 별도의 줄 분리·결합·삭제 테스트에서 코드 글꼴, 커서 위치, 다음 줄의 색상을 검증했다.

Windows x64, .NET 11 Release에서 한글·영문 가사 192줄에 코드 줄 64개와 `[region 2]` 표식 32개를 배치했다. 서식 처리 함수만 3회 예열한 뒤 7개 구간의 호출당 중앙값을 측정했다. 할당량은 호출 스레드의 관리 힙 기준이다.

| 서식 갱신 범위 | 수정 전 시간 | 수정 후 시간 | 수정 전 할당 | 수정 후 할당 | 수정 전후 Refresh 호출 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 가사 한 줄 | 15.65 ms | 0.48 ms | 1,992,800 B | 39,288 B | 33회 → 1회 |

## PowerPoint 썸네일과 자동 전환 시간표

미리보기·송출 패널과 곡·안내 화면 편집기에서 각각 1,025번째 항목을 열었을 때 `IndexOutOfRangeException`을 재현했다.

| 대상 | 자료구조 변경 | 회귀 검증 |
|---|---|---|
| PowerPoint 미리보기·송출 | 패널의 컨트롤 컬렉션이 슬라이드 순서와 썸네일을 소유한다. 이미지 경로는 캐시 접두사와 슬라이드 번호에서 계산한다. 장수가 줄면 초과 컨트롤과 툴팁 연결을 해제한다. | 두 패널에서 1,024 → 1,025 → 3장 전환, 마지막 JPEG 디코딩, 선택 상태 독립성, 제거된 썸네일 해제를 확인했다. 미리보기의 실제 WinForms 스크롤 영역에서 마지막 장과 첫 장으로 이동했다. |
| 곡·안내 화면 편집기의 자동 전환 시간표 | 행마다 구절 번호·표시 이름·초를 저장한다. 화면에 보이는 행에만 레이블과 시간 입력기를 배치한다. 저장할 때 양수인 시간을 정렬해 기존 구분자로 기록한다. | 두 편집기에서 마지막 행까지 스크롤해 시간을 바꾸고 저장했다. 3행으로 줄인 뒤 다시 늘려도 제거된 시간이 되살아나지 않았다. 반복 구절, 같은 시간 두 개, 재생 위치 추가와 전체 지우기도 검증했다. |

Windows Release 솔루션 테스트 2,674개가 통과했다. 운영 레지스트리 `HKCU\Software\EasiSlides`의 32비트·64비트 보기에서 작업 전후 값의 SHA-256이 각각 일치했다.
