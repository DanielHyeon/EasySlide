### 가사·이조·3.2 파일의 문자열 처리

곡 이조는 원문에서 줄 번호와 코드·위치 쌍을 차례로 읽고 결과 문자열 하나를 조립한다. 두 가사 형식은 줄과 코드 레코드를 읽는 코드를 공유한다. 기존 형식에서 새 절이 제1영역으로 돌아가는 규칙과 새 형식에서 제2영역을 유지하는 규칙은 각각 테스트했다. 3.2 파일 변환도 필드를 원문에서 읽어 저장할 키와 값을 순서대로 쓴다.

고정 시드로 생성한 입력 500세트에서 구·신형 가사 양쪽의 행과 영역별 텍스트·코드, 이조 결과, 3.2 헤더와 메타데이터를 기존 결과와 대조했다. 별도의 회귀 테스트로 `[region 2]`만 있는 곡을 읽을 때 발생하던 예외를 재현했고, 수정 후 빈 가사 목록이 반환되는 것을 확인했다.

Windows x64, .NET 11 Release, 한국어 설정에서 입력별 15회 예열 후 7회 측정한 호출당 중앙값이다. 각 회차는 이조 60회, 가사 읽기 25회, 3.2 변환 80회다. 가사 읽기에는 WinForms 목록을 만들고 해제하는 비용이 포함된다.

## PowerPoint 썸네일과 자동 전환 시간표

미리보기·송출 패널과 곡·안내 화면 편집기에서 각각 1,025번째 항목을 열었을 때 `IndexOutOfRangeException`을 재현했다.

| 대상 | 자료구조 변경 | 회귀 검증 |
|---|---|---|
| PowerPoint 미리보기·송출 | 패널의 컨트롤 컬렉션이 슬라이드 순서와 썸네일을 소유한다. 이미지 경로는 캐시 접두사와 슬라이드 번호에서 계산한다. 장수가 줄면 초과 컨트롤과 툴팁 연결을 해제한다. | 두 패널에서 1,024 → 1,025 → 3장 전환, 마지막 JPEG 디코딩, 선택 상태 독립성, 제거된 썸네일 해제를 확인했다. 미리보기의 실제 WinForms 스크롤 영역에서 마지막 장과 첫 장으로 이동했다. |
| 곡·안내 화면 편집기의 자동 전환 시간표 | 행마다 구절 번호·표시 이름·초를 저장한다. 화면에 보이는 행에만 레이블과 시간 입력기를 배치한다. 저장할 때 양수인 시간을 정렬해 기존 구분자로 기록한다. | 두 편집기에서 마지막 행까지 스크롤해 시간을 바꾸고 저장했다. 3행으로 줄인 뒤 다시 늘려도 제거된 시간이 되살아나지 않았다. 반복 구절, 같은 시간 두 개, 재생 위치 추가와 전체 지우기도 검증했다. |

Windows Release 솔루션 테스트 2,674개가 통과했다. 운영 레지스트리 `HKCU\Software\EasiSlides`의 32비트·64비트 보기에서 작업 전후 값의 SHA-256이 각각 일치했다.

## 가사 미리보기·송출과 편집기 실행 취소

| 대상 | 변경 | 검증 |
|---|---|---|
| 가사 미리보기·송출 | 두 패널에서 시작할 때 예약하던 컨트롤 참조 60,000칸을 제거했다. 실제 슬라이드별 본문과 높이를 저장하고 보이는 범위에서만 RichTextBox를 사용한다. 새로 보이는 행은 실제 RichEdit 줄바꿈 높이로 보정한다. | Windows의 320×200 테스트 패널에서 30,001번째 가사와 선택 색상을 확인했다. 두 패널에서 각각 12개 이하의 RichTextBox로 표시했다. 3장과 빈 화면으로 전환, 한글·영문 줄바꿈과 창 너비 변경, 스크롤 후 클릭한 장 번호, 두 언어 영역과 선택 범위도 검증했다. |
| 곡·안내 화면 편집기 실행 취소 | 언어 영역마다 최대 101개 상태를 담는 원형 버퍼에 RTF와 커서 위치를 함께 기록한다. 새 편집은 폐기한 다시 실행 기록의 참조를 해제하고, 새 곡을 열면 해당 기록을 초기화한다. | 수정 전에는 102회 편집 후 두 번 되돌려도 두 편집기 모두 101번째 내용에 머물렀다. 수정 후에는 100번째 내용과 커서가 복원된다. 동일 테스트에서 100단계 경계, 되돌린 뒤 새로 입력, RTF 서식의 왕복, 두 영역의 독립성과 초기화를 확인했다. |

Release 솔루션 테스트 2,680개가 통과했다. 작업 전후 운영 레지스트리 `HKCU\Software\EasiSlides`의 32비트·64비트 보기를 읽어 비교한 SHA-256이 각각 일치했다.

네 가지 배열 개선과 필요한 슬라이드 버퍼·편집기 서식 변경만 담은 별도 작업 트리에서도 Release 솔루션 테스트를 실행했다. WinForms 97개, WPF 2,461개, 분석기 20개로 총 2,578개가 통과했다.
