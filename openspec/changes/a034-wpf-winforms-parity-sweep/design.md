## 기준

두 앱이 다르면 WinForms 코드를 읽어 기준으로 삼는다. WinForms 쪽이 데이터를 잃거나 예외를 내면 WinForms를 고치고 WPF는 고친 동작을 따른다.

## 예외와 PowerPoint

- `OperationalErrorLog`는 쇼가 실행 중일 때 디스패처 예외를 처리 완료로 표시하고 상태 줄에 알린다. 10초 안에 5번을 넘으면 다시 종료 경로로 넘긴다.
- `OfficePptSession`은 COM 호출 종류마다 제한 시간을 둔다(넘기기와 읽기 5초, 시작 60초, 닫기 10초). 제한을 넘긴 호출은 버리고 작업 스레드를 다시 만든다.
- `MayQuit`는 앱보다 먼저 떠 있던 보이는 PowerPoint와 제한된 보기 창이 있는 PowerPoint를 종료하지 않는다. 쇼는 원본의 복사본으로 연다.

## 가사와 코드

- `LyricsDisplayFormatter.ReadVerses`가 gfLyrics의 절, 화면, 영역 2 규칙을 한 곳에서 구현한다. 빈 줄은 화면을 나누고 공백만 있는 줄은 화면의 한 줄이다.
- 저장된 코드는 `LiveQueueItem.Notations`에 두고 `LyricsWithChords`가 가사 줄에 붙인다. 가사 원문(`Lyrics`)은 바꾸지 않으므로 편집과 내보내기에 영향이 없다.
- `LyricParagraphSurface`는 각 코드를 해당 글자의 왼쪽 끝에 그린다. 가사 줄이 여러 행으로 접히면 행마다 코드 행을 둔다. 코드가 있는 페이지가 넘치면 글자를 줄인다. 페이지 수는 코드 표시 여부와 무관하다.

## 예배 순서

- 이름 있는 목록은 편집 후 디스패처 Background 우선순위에서 한 번 저장한다. 한 동작의 여러 변경은 한 번의 쓰기다.
- 삭제와 비우기는 화면의 목록을 먼저 저장한 뒤 파일을 휴지통으로 옮긴다. 복원할 이름이 이미 있으면 복원본에 시각을 붙인다.
- 손상된 목록 파일은 빈 목록이 아니라 읽기 오류다. 화면의 목록과 쇼는 그대로 둔다.
- 송출 중인 행은 곡 ID가 아니라 행 자체로 추적한다. 같은 곡이 두 번 있어도 LIVE 표시는 한 행에만 붙는다.

## 곡 편집기와 라이브러리

- 편집기는 영역 1과 영역 2 칸을 따로 두고 저장할 때 `Merge_Songs` 규칙으로 합친다. 화면에 보이는 코드 줄이 저장되지 않는 경우는 저장을 거부한다.
- 곡 쓰기는 백업 1회와 트랜잭션 1회로 묶는다. 백업은 최근 20개, 최근 30일의 하루 첫 사본, 매월 첫 사본을 남긴다.
- 폴더 번호는 1~40을 재사용한다. 삭제된 곡이 가리키는 번호는 새 폴더에 주지 않는다.

## 설정

- 첫 실행에서 `%AppData%\Axicultuss\settings.json`을 가져온다. 이 파일이 없을 때만 레지스트리를 읽는다. 가져온 `root_directory`를 쓰므로 두 앱이 같은 데이터 폴더를 읽고 쓴다.
- 송출 창 단축키(D H R S O I V N)는 쇼가 끝나면 저장된 값으로 되돌린다. 쇼 도중 앱이 비정상 종료되면 바뀐 값이 남는다.

## 검증 방법

실제 교회 데이터가 있는 PC이므로 앱은 격리 프로필과 데이터 사본으로만 실행한다. 실행 전후로 실제 데이터 폴더 세 곳의 해시와 레지스트리 내보내기를 비교한다. 모니터가 2대 미만이거나 앱이 이미 실행 중이면 실행하지 않는다.
