## Why

WPF 운영 콘솔을 WinForms 원본과 나란히 실행해 보니 예배 중 앱이 종료되는 예외, 송출 화면이 원본과 다르게 나오는 경우, 저장한 내용이 사라지는 경로가 있었다. 예배 중에는 고칠 시간이 없으므로 WPF가 WinForms와 같은 화면을 내고 같은 데이터를 남겨야 한다.

## What Changes

- 예배 중 처리되지 않은 예외는 앱을 종료하지 않고 상태 줄에 알린다.
- PowerPoint가 응답하지 않아도 운영 콘솔이 멈추지 않는다. 운영자가 직접 연 PowerPoint는 닫지 않는다.
- 가사 화면 분할, 순서(Sequence), 2개 언어 짝 맞춤을 WinForms 규칙으로 맞춘다. 실제 곡 DB 전체에서 결과가 같다.
- DB에 저장된 코드(MSC)를 미리보기, 송출, 스테이지 화면의 음절 위에 표시한다.
- 예배 순서는 편집할 때마다 저장한다. 삭제와 비우기는 휴지통으로 보내고 복원할 수 있다.
- 곡 편집기에 영역 2 편집 칸, 코드 편집, 폴더 변경을 추가하고 저장 규칙을 FrmEditItem과 맞춘다.
- 곡 여러 개를 한 번에 복사, 이동, 삭제한다. 가져오기와 병합은 전부 성공하거나 전부 취소한다.
- 쇼 중 항목 사이 간격 화면, 송출 창 단축키, 숨김과 블랙의 독립 동작을 추가한다.
- 설정 첫 실행 시 WinForms 설정을 가져오고, 기본값을 WinForms와 맞춘다.
- 같은 결함이 WinForms에도 있으면 함께 고친다.

## Capabilities

### New Capabilities

- `wpf-winforms-parity` WPF 운영 콘솔이 WinForms 원본과 같아야 하는 송출, 데이터, 안전 동작을 정의한다.

## Impact

범위는 `Axicultus/`(WPF), `Axicultus.Core/`, `Axicultuss/`(WinForms)와 각 테스트 프로젝트다. DB 스키마는 바꾸지 않는다. 예배 순서 파일에는 곡의 코드(`Notations`) 항목이 추가되며 이전 파일은 그대로 읽는다. 설치된 `C:\Axicultus` 빌드는 이 변경으로 교체하지 않는다.
