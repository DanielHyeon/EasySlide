## ADDED Requirements

### Requirement: 예배 중 앱 유지
쇼가 실행 중일 때 처리되지 않은 UI 예외는 앱을 종료하지 않아야 한다(SHALL).

#### Scenario: 쇼 도중 예외 발생
- **WHEN** 쇼가 실행 중이고 화면 처리 코드에서 예외가 발생한다.
- **THEN** 송출은 계속되고 상태 줄에 오류를 표시하며 오류 기록을 남긴다.

### Requirement: PowerPoint 응답 지연
PowerPoint가 응답하지 않아도 운영 콘솔은 제한 시간 안에 조작을 돌려받아야 한다(SHALL).

#### Scenario: PowerPoint가 멈춘 상태에서 다음 슬라이드
- **WHEN** PowerPoint 프로세스가 멈춘 상태에서 다음 슬라이드 키를 누른다.
- **THEN** 약 6초 안에 실패를 알리고, 밀린 키 입력을 나중에 한꺼번에 실행하지 않는다.

#### Scenario: PowerPoint가 종료된 뒤 슬라이드 이동
- **WHEN** 쇼 도중 PowerPoint가 종료되고 운영자가 슬라이드를 고른다.
- **THEN** PowerPoint를 다시 시작해 그 슬라이드를 송출한다.

### Requirement: 운영자의 PowerPoint 보호
앱은 운영자가 직접 열어 둔 PowerPoint와 그 문서를 닫지 않아야 한다(SHALL).

#### Scenario: PowerPoint가 열린 상태에서 쇼 실행 후 종료
- **WHEN** 운영자가 PowerPoint로 문서를 열어 둔 채 앱에서 PPT 항목을 송출하고 쇼와 앱을 끝낸다.
- **THEN** 같은 PowerPoint 프로세스가 남고 운영자의 문서가 그대로 열려 있으며 쇼 창은 없다.

### Requirement: 가사 화면 분할
WPF는 같은 곡을 WinForms와 같은 절, 화면, 영역 2 짝으로 나누어야 한다(SHALL).

#### Scenario: 공백만 있는 줄
- **WHEN** 절 안에 공백만 있는 줄이 있다.
- **THEN** 그 줄은 화면을 나누지 않고 화면의 한 줄로 표시한다.

#### Scenario: 첫 표시 앞의 가사와 1절
- **WHEN** 첫 절 표시 앞에 가사가 있고 뒤에 `[1]`이 있다.
- **THEN** 두 부분을 한 절로 다룬다.

#### Scenario: 실제 곡 DB 전체
- **WHEN** 실제 곡 DB의 모든 곡을 두 규칙으로 나눈다.
- **THEN** 화면 수와 화면 내용이 모든 곡에서 같다.

#### Scenario: 2개 언어 곡의 영역 1이 자리보다 높다
- **WHEN** 자동 텍스트 넘김이 켜져 있고 2개 언어 곡의 영역 1이 영역 2 위의 자리에 다 들어가지 않는다.
- **THEN** 영역 1을 측정해 화면을 나누고, 나뉜 화면마다 영역 2에서 영역 1과 같은 수의 줄을 가져가며 마지막 화면이 나머지를 가져간다.

#### Scenario: 영역 2만 있는 절
- **WHEN** 2개 언어 곡의 한 절에 영역 2 가사만 있다.
- **THEN** 그 절은 영역 2의 글꼴과 자리로 측정해 화면을 나눈다.

### Requirement: 저장된 코드 표시
코드 표시가 켜져 있으면 DB에 저장된 코드(MSC)를 해당 음절 위에 표시해야 한다(SHALL).

#### Scenario: 한 행에 들어가는 가사 줄
- **WHEN** 코드가 저장된 곡을 송출하고 코드 표시가 켜져 있다.
- **THEN** 각 코드가 저장된 글자의 왼쪽 끝 위에 놓인다.

#### Scenario: 여러 행으로 접히는 가사 줄
- **WHEN** 글꼴이 커서 가사 줄이 두 행 이상으로 접힌다.
- **THEN** 각 코드는 자기 글자가 있는 행 위에 놓인다.

#### Scenario: 조옮김과 표시 끄기
- **WHEN** 송출 중 조옮김을 하거나 코드 표시를 끈다.
- **THEN** 코드 이름만 바뀌고 위치는 그대로이며, 끄면 코드 없는 화면과 같다.

### Requirement: 예배 순서 보존
예배 순서의 편집 내용은 저장 명령 없이도 파일에 남아야 하고, 삭제한 목록은 복원할 수 있어야 한다(SHALL).

#### Scenario: 편집 직후 앱이 종료됨
- **WHEN** 이름 있는 목록에 행을 추가하고 저장하지 않은 채 앱이 종료된다.
- **THEN** 다시 열면 추가한 행이 목록에 있다.

#### Scenario: 편집 후 비우기와 복원
- **WHEN** 행을 추가한 직후 목록을 비우고 휴지통에서 복원한다.
- **THEN** 복원한 목록에 추가한 행이 있고, 같은 이름의 목록을 덮어쓰지 않는다.

#### Scenario: 손상된 목록 파일
- **WHEN** 내용이 잘린 목록 파일을 연다.
- **THEN** 화면의 목록과 쇼는 그대로이고 상태 줄에 읽기 오류를 표시한다.

### Requirement: 송출 상태 조작
블랙, 지우기, 숨김은 서로 독립이어야 하고, 항목 이동은 출력 상태와 무관하게 같은 페이지를 열어야 한다(SHALL).

#### Scenario: 숨김 중 블랙 켜고 끄기
- **WHEN** 출력을 숨긴 뒤 블랙을 켰다가 끈다.
- **THEN** 출력은 계속 숨김 상태다.

#### Scenario: 블랙 중 다음 항목
- **WHEN** 블랙 상태에서 다음 항목으로 이동하고 블랙을 끈다.
- **THEN** 새 항목의 첫 페이지가 나온다.

#### Scenario: 송출 창 단축키
- **WHEN** 쇼 도중 송출 창에서 그림자나 코드 표시 단축키를 누르고 쇼를 끝낸다.
- **THEN** 쇼 동안만 바뀌고, 끝난 뒤 저장된 설정은 누르기 전과 같다.

### Requirement: 곡 편집 저장
곡 편집기는 화면에 보이는 가사와 코드를 저장하거나, 저장할 수 없으면 이유를 알리고 거부해야 한다(SHALL).

#### Scenario: 수정하지 않고 저장
- **WHEN** 실제 곡을 열어 아무것도 바꾸지 않고 저장한다.
- **THEN** 코드는 저장된 값과 같고, 가사는 FrmEditItem이 저장하는 내용과 같다.

#### Scenario: 편집 중 예외
- **WHEN** 가사 칸의 내용 처리에서 오류가 난다.
- **THEN** 이전 내용을 저장하지 않는다.

### Requirement: 왼쪽 열 너비
폴더 탭과 예배 순서가 있는 왼쪽 열은 창 너비와 무관하게 좁힐 수 있어야 한다(SHALL).

#### Scenario: 넓은 창에서 왼쪽 열 줄이기
- **WHEN** 넓은 창에서 왼쪽 열의 경계를 왼쪽으로 끈다.
- **THEN** 두 앱 모두 왼쪽 열이 최소 너비까지 줄어든다.
