# Tasks: PPT 항목이 시작되지 못했거나 다른 프레젠테이션이 활성일 때 엉뚱한 프레젠테이션을 조작하는 문제 수정

구현 → 적대적 리뷰 → 내장 코드 리뷰 → 총괄 검증 → 커밋.

## 1. 먼저 확인할 것 (수정 전 빌드)

- [x] 1.1 `Run`이 성공한 뒤 `ActivePresentation`이 무엇인지 (방금 실행한 것인지). 모니터 둘 방식의 두 번 실행(메인 화면, 송출 창) 각각의 뒤
- [x] 1.2 쇼 시작 → 끝 → 다시 시작: 두 번째 쇼에서 `MainPPT.Run`의 결과와, 메인 화면의 키가 프로젝터의 슬라이드를 넘기는지. PowerPoint 프로세스 수
- [x] 1.3 실행이 실패한 항목 뒤의 상태를 기록한다 (프로젝터, 상태 줄, 절 버튼, 키의 동작). 실패는 임시 스위치로 만든다

## 2. 구현

- [x] 2.4 P4: 메인 화면의 송출 단 그림, 송출 상태 줄(`PowerPoint: NOT STARTED`), 꺼진 모양. 슬라이드 쇼가 도중에 사라진 경우의 알림

## 3. 확인

- [x] 3.1 정상 동작이 그대로다: PPT 항목 송출, 슬라이드 앞뒤 이동, 처음/끝, 절 버튼, 썸네일 클릭, PPT A → PPT B → 가사 → PPT A, 쇼 끝내기와 재시작
- [x] 3.2 실행이 실패한 항목: 프로젝터에 기본 배경, 메인 화면에 `PowerPoint: NOT STARTED`와 알림 한 번, 키를 눌러도 이전 항목의 슬라이드가 넘어가지 않는다. 그 뒤 정상 항목은 정상으로 송출된다
- [x] 3.3 다른 프레젠테이션이 활성일 때 (앱이 연 다른 복사본을 활성으로 만들어 시험): 키가 송출 중인 항목의 슬라이드를 넘긴다
- [x] 3.4 슬라이드 이동 오류를 일으켜도 미리보기 항목이 송출되지 않는다
- [x] 3.5 쇼를 끝내고 다시 시작한 뒤 메인 화면의 키가 프로젝터의 슬라이드를 넘긴다
- [x] 3.6 미리 열기 실패 알림 (임시 스위치)

## 4. 리뷰 반영

- [x] 4.1 찾음 / 사라짐 / 알 수 없음. 사라짐은 확실히 확인된 경우에만. 읽히지 않는 후보는 건너뛴다
- [x] 4.2 끝남은 고정되지 않는다. 다음 조작에서 다시 확인한다
- [x] 4.3 마지막 슬라이드에서 슬라이드 쇼가 끝나는 경우를 항목의 끝으로 처리한다
- [x] 4.4 메인 화면이 송출 창의 실행을 이어받는다. 두 실행의 결과가 다르면 송출 창을 따른다 (항목 이동 키, 자동 다음 항목 포함)
- [x] 4.5 미리 열기 때 MainPPT의 연결이 죽었으면 다시 붙인다. 실패하면 알린다
- [x] 4.6 미리보기 썸네일 더블클릭이 송출 중인 슬라이드 쇼를 건드리지 않는다
- [x] 4.7 알림 중복 제거, 쇼 단위 상태 초기화, 송출 창 쪽 슬라이드 번호 보정

## 5. 확인 못 한 것

- 실패 경로(시작되지 못한 항목, 알 수 없는 오류, 슬라이드 쇼가 끝난 경우, 이어받기 실패, 연결이 죽은 경우)는 구현 담당이 임시 스위치로 만든 상황에서 확인했다. 총괄은 정상 동작 14단계(슬라이드 앞뒤, 마지막에서 다음, 항목 이동, PPT A → B → 가사 → A, 끝내기와 재시작)를 프로젝터 캡처의 쪽 번호와 상태 줄로 확인했다
- 실제 상황: PowerPoint가 바쁠 때(창이 떠 있을 때), PowerPoint가 종료됐을 때, 프로젝터의 슬라이드 쇼에서 Esc, 사용자의 문서가 같은 PowerPoint에 열려 있을 때
- PowerPoint의 "검은 슬라이드로 끝내기"가 꺼진 설정 (이 PC는 기본값인 켜짐. 꺼진 경우는 흉내만 냈다)
- 모니터 하나 방식, 라이브 카메라와 비디오 항목(창 줄이기), Remote_SongJumpTo 경로
- 처음/끝 슬라이드와 절 버튼은 키 입력이 아니라 같은 내부 함수 호출로 확인했다 (이 목록의 PPT에는 절 표시가 없다)
