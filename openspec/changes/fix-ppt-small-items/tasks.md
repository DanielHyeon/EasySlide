# Tasks: PowerPoint 경로의 남은 작은 문제들

구현 → 적대적 리뷰 → 내장 코드 리뷰 → 총괄 검증 → 커밋.

## 1. 먼저 확인할 것

- [x] 1.1 복사본에 태그를 달면 닫을 때 저장 확인 창이 뜨는지, 어떻게 하면 뜨지 않는지 (별도 프로그램으로, 테스트용 파일만 쓴다)
- [x] 1.2 `PowerpointList`의 번호를 쓰는 곳 (S2의 항목 교체가 안전한지)
- [x] 1.3 절 읽기에서 "메모 자리가 없음"과 다른 오류를 구분할 수 있는지

## 2. 구현

- [x] 2.1 S1: 앱이 연 복사본에 표시. `Run`, 실행 뒤의 찾기, 닫기, 창 줄이기가 표시를 확인한다
- [x] 2.2 S2: 경로로 찾을 때 살아 있는 항목을 쓴다. 다시 연 복사본은 옛 항목을 바꾼다
- [x] 2.3 S3: 쇼 끝에서 닫지 못한 프레젠테이션을 알린다
- [x] 2.4 S4: 절 캐시의 수정 시각 순서, 오류가 난 결과는 캐시하지 않음
- [x] 2.5 S5: `ProcessKill`이 프로세스 하나의 실패로 멈추지 않는다
- [x] 2.6 S6: 쓰이지 않는 코드 삭제
- [x] 2.7 S7: 쇼 도중의 파일 수 제한 알림, 메시지 창의 소유 창

## 3. 확인

- [x] 3.1 정상 동작이 그대로다: 쇼 시작, PPT 항목 송출, 슬라이드 앞뒤, PPT A → B → 가사 → A, 쇼 끝내기(복사본이 모두 닫히고 저장 확인 창이 뜨지 않는다), 재시작, 앱 종료 뒤 PowerPoint가 남지 않는다
- [x] 3.2 S1: 표시가 없는 같은 이름의 프레젠테이션은 실행되지도 닫히지도 않는다 (임시 스위치나 별도 프로그램으로)
- [x] 3.3 S2: 쇼 도중 복사본이 닫힌 뒤 다시 미리 열기가 일어나면 그 항목이 다시 시작된다
- [x] 3.4 S3: 닫기 실패 알림 (임시 스위치)
- [x] 3.5 S4: 절 버튼이 지금처럼 나온다. 수정 시각 순서는 별도 프로그램으로
- [x] 3.6 S5, S6: 빌드, 앱 시작과 종료

## 4. 리뷰 반영

- [x] 4.1 같은 이름의 목록 항목을 모두 확인해 표시가 맞는 것을 찾는다 (옛 항목이 살아 있는 복사본을 가려 쇼 끝에 닫히지 않던 것)
- [x] 4.2 새 복사본이 이름을 받으면 같은 이름을 가진 다른 항목의 이름을 비운다
- [x] 4.3 실행 단계마다 "저장됨" 표시가 유지되는지 확인 (유지된다. 추가 조치 없음)
- [x] 4.4 실제 PPT에서 이름, 전체 이름, 슬라이드 쇼 창 제목 확인

## 5. 확인 못 한 것

- 앱 안에서: 쇼 도중 복사본이 닫힌 뒤의 다시 열기, PowerPoint가 다시 시작된 뒤 이름이 겹치는 경우, 표시가 없는 같은 이름의 문서. 별도 프로그램과 테스트용 파일로만 확인했다 (목록을 바꾸지 않고는 쇼 도중 미리 열기를 일으킬 수 없다)
- 실제 닫기 실패 (임시 스위치로만), 시작 때 정리 도중 프로세스가 사라지는 경우
- 절 버튼이 이전과 같게 나오는지 (이 목록의 PPT에는 절 표시가 없다. 캐시 동작은 별도 프로그램으로 확인)
- 모니터 하나 방식, 쇼 밖에서 뜨는 메시지 창의 소유 창
- 총괄은 정상 동작 14단계(슬라이드 앞뒤, 마지막에서 다음, PPT A → B → 가사 → A, 끝내기, 재시작)를 프로젝터 캡처와 상태 줄로 확인했고, 쇼를 끝낸 뒤 PowerPoint 창이 남지 않는 것과 앱 종료 뒤 PowerPoint가 남지 않는 것을 확인했다
