# Design: 화면 그리기 쪽에 남은 문제들

## 확인된 것 (코드로)

- `ImageTransitionControl.PaintScreen`의 `Rectangle` 분기는 `Draw_CurrentImage` → 잘라낼 사각형 설정 → `//Draw_NewImage(e);`(주석) 순이다. `RectangleIn` 분기는 `Draw_NewImage` → 잘라낼 사각형 설정 → `//Draw_CurrentImage(e);`(주석)이다. 다른 모양 전환(바둑판, 원, 별 등)은 잘라낸 영역 안에 다른 그림을 그린다.
- 화면마다 층(글자, 패널)의 버퍼는 둘씩이고, 그릴 때마다 만드는 합성 그림은 화면이 소유 목록으로 추적해 해제한다 (`fix-show-window-lifecycle`). 배경 그림(`NewBackgroundPicture`, `CurrentBackgroundPicture`)과 처음 만든 복제본은 그 추적에 들어 있지 않다.
- `Dispose`는 화면이 자기 것이라고 증명할 수 있는 그림만 해제한다. 다른 코드(`gfUtility`)가 `BackgroundImage` 등을 직접 넣기 때문이다.

나머지 항목(2~7)은 조사와 리뷰에서 지적된 것이고, 구현 전에 각각 코드와 측정으로 다시 확인한다 (tasks.md 1절). 확인되지 않는 항목은 고치지 않고 이유를 적는다.

## Decisions

### G1. 사각형 전환

`Rectangle`과 `RectangleIn`이 잘라낸 영역 안에 다른 쪽 그림을 그린다. 같은 종류의 다른 전환(원 등)이 쓰는 순서와 방식을 그대로 따른다. 주석으로 막힌 이유를 git 이력에서 찾아보고, 이유가 있었으면 그 문제를 다시 일으키지 않는 방식으로 한다. 프레임이 끝날 때 잘라내기 영역이 남지 않게 한다 (알림, 참조 표시가 그 뒤에 그려진다).

### G2. 전환 프레임의 자원

프레임마다 만드는 작업용 비트맵과 `Graphics`, `GraphicsPath`, 붓과 펜은 그 프레임이 실패해도 해제한다 (`try/finally` 또는 `using`). 그리는 순서와 결과는 바꾸지 않는다. `_imageWorkSpace`처럼 필드에 넣는 것은, 해제한 뒤에도 필드가 그 객체를 가리키는 지금의 방식을 유지한다 (다른 코드가 참조만 비교한다. `fix-show-window-lifecycle`에서 확인).

프레임마다 화면 크기의 비트맵을 새로 만드는 것 자체(성능)는 이번에 바꾸지 않는다.

### G3. 글꼴

- 알림과 참조 표시의 글꼴은 값(이름, 크기, 모양)이 같으면 다시 쓴다. 가사 글꼴에 이미 있는 캐시(`RenderingCache.GetFont`)를 쓸 수 있으면 그것을 쓴다. 캐시된 글꼴은 호출한 쪽이 해제하지 않는다.
- 캐시를 쓸 수 없는 곳은 쓰고 나서 해제한다. 해제한 글꼴이 다른 객체(컨트롤의 `Font` 등)에 남아 쓰이지 않는지 확인한다.

### G4, G5. 배경 그림의 소유

화면이 스스로 만든 배경 그림 복제본은 화면이 소유한다. 소유한 그림은 다른 그림으로 바뀔 때와 화면이 폐기될 때 해제한다. 합성 그림에 쓰는 소유 목록과 같은 방식으로 한다 (그림마다 "화면이 만든 것"인지 기록하고, 화면의 어느 필드도 더는 가리키지 않을 때 해제).

- 다른 코드가 넣은 그림(`BackgroundImage`, 공유 캐시의 그림)은 화면의 것이 아니다. 해제하지 않는다.
- 복제 자체가 필요 없는 곳(같은 그림을 다시 복제하는 경우)은 복제하지 않는다.
- PPT 항목의 슬라이드를 바꿀 때 쌓이는 약 10MB의 출처를 측정으로 찾아서, 위 규칙에 해당하면 고친다. 다른 원인이면 보고만 한다.

### G6. 썸네일 스크롤

`LoadThumbOutImages`의 `ScrollControlIntoView` 호출을 그 함수의 예외 처리 안으로 넣는다. 미리보기 쪽의 같은 함수도 확인한다.

### G7. 쇼 진행 중의 앱 종료

메인 화면이 닫힐 때 쇼가 진행 중이면, 닫기 전에 쇼를 끝내기 버튼과 같은 경로로 끝낸다 (`GoLive(false)`: 송출 창 정리, 슬라이드 쇼 내리기와 닫기, 작업 표시줄과 화면 보호기 복원). 그 과정에서 예외가 나도 앱 종료는 계속된다. 종료 순서의 다른 부분(설정 저장, PowerPoint 놓기)은 바꾸지 않는다. Windows 종료나 작업 관리자의 종료에서도 같은 경로를 타는지, 타면 시간이 걸리는 작업이 종료를 막지 않는지 확인한다.

## 리뷰 뒤에 정한 것

적대적 리뷰와 내장 코드 리뷰(2026-11-17)에서 나온 것이다.

### G7a. 취소된 닫기와 Windows 종료

- `Form1_FormClosing`이 불렸을 때 `e.Cancel`이 이미 참이면(소유한 창이 닫기를 취소) 아무것도 하지 않는다. 지금은 닫히지 않는데도 PowerPoint를 놓고 후킹을 풀고 임시 폴더를 지운다 (이번 작업 이전부터 있던 문제). 쇼도 끝내지 않는다.
- Windows 종료(`CloseReason.WindowsShutDown`)에서는 `FormClosing`이 "종료해도 되는지 묻는" 단계(`WM_QUERYENDSESSION`)에서 불린다. 다른 프로그램이나 사용자가 종료를 취소하면 앱은 그대로 살아 있다. 그래서 이 단계에서는 되돌릴 수 없는 일을 하지 않는다. 쇼 끝내기를 포함한 닫기 작업 전체를, 종료가 확정됐을 때(`FormClosed`) 한 번만 실행한다. 송출 창의 `FormClosing`도 같은 규칙을 따른다 (지금은 묻는 단계에서 쇼 정리를 실행한다).
- 닫기 작업의 내용과 순서는 바꾸지 않는다. 실행 시점만 옮긴다. 두 번 실행되지 않게 한다.
- 확인은 시험 인스턴스의 창에 `WM_QUERYENDSESSION`과 `WM_ENDSESSION`(취소된 경우와 확정된 경우)을 보내서 한다.

### G7b. 창 하나로 쇼를 띄운 경우 (모달)

단일 모니터 방식에서는 `Start_Presentation`이 `ShowDialog` 안에서 기다린다. 그 상태에서 메인 화면이 닫히면 `ShowDialog` 뒤의 코드가 이미 닫힌 메인 화면을 건드린다 (이번 작업 이전부터 있던 문제). 메인 화면이 닫히는 중이면 그 뒤처리를 건너뛴다. 쇼 정리(작업 표시줄 복원 포함)는 G7대로 실행한다.

### G5a. 기본 배경 그림

`SetDefaultBackScreen`이 화면마다 따로 만들어 넣는 `BackgroundImage`도, 그 화면만 쓰는 것이 확인되면 화면의 것으로 삼는다 (새 그림으로 바뀌고 어느 필드도 가리키지 않을 때, 그리고 화면이 폐기될 때 해제). 여러 화면이나 캐시가 같은 객체를 함께 쓰면 그대로 두고 이유를 적는다.

### 그 밖

- 화면이 만든 그림은 필드에 넣는 시점에 소유 목록에 올린다 (그리다 실패한 그림이 목록에 남지 않게).
- 프레임 작업용 비트맵을 만들 때 그 자리에 있던 그림을 놓아 준다.
- `RectangleIn`의 사각형은 가장자리에서 안쪽으로 계산한다 (너비가 홀수일 때 첫 프레임의 1픽셀 줄).
- 썸네일 스크롤은 예외를 잡는 대신 번호를 배열 범위와 비교한다.

## 구현하면서 정한 것

- **사각형 전환의 주석**: git 이력에는 이유가 없다. 옆 폴더의 옛 소스를 보면 2020-11의 수정에서 여러 해제 호출과 함께 한꺼번에 주석 처리됐다. 기능상의 이유는 남아 있지 않다.
- **`RectangleIn`의 그리는 순서**: 주석을 그대로 풀지 않고 다른 모양 전환과 같은 순서로 했다 (이전 그림 → 잘라내기 → 새 그림). 주석을 그대로 풀면 알림과 참조 글자가 줄어드는 사각형 안에만, 두 번 그려진다.
- **프레임 자원**: 프레임이 만드는 비트맵, `Graphics`, 경로, 영역, 행렬을 한 목록에 올리고 프레임이 끝날 때(예외 포함) 해제한다. 분기 안의 기존 해제 호출은 그대로 뒀다 (두 번 해제해도 문제없다). 덮어써서 잃어버리던 행렬과 쓰이지 않던 경로도 함께 해제된다.
- **글꼴**: 알림과 참조 표시의 준비용 글꼴은 준비가 끝나면 해제한다 (어디에도 저장되지 않는다). `ReferenceAlertFont`, `Alert_UserFont`는 요청(이름, 크기, 모양)이 같으면 다시 쓰고, 바뀌면 이전 것을 해제한다. 가사 글꼴 캐시(`RenderingCache`)는 크기를 정수로 구분해서, 소수 크기가 다른 글꼴을 돌려줄 수 있어 쓰지 않았다.
- **그림의 소유**: 화면의 소유 목록(`_ownImages`)에 합성 그림, 배경 그림, 처음 만든 복제본, 기본 배경 그림을 올린다. 그림 속성에 새 값을 넣을 때 이전 값을, 화면의 어느 필드도 가리키지 않으면 해제한다. 화면이 폐기될 때는 목록에 있는 것만 해제한다. 층 버퍼는 지금처럼 따로 관리한다.
- **복제를 옮기기로**: `NewBackgroundPicture`를 `CurrentBackgroundPicture`로 넘길 때 복제하지 않고 그 객체를 그대로 넘긴다. 배경 그림은 만든 뒤에 누구도 그 위에 그리지 않는다 (확인).
- **PPT 슬라이드마다 약 10MB**: 수정 전 빌드에서 재현되지 않았다. 슬라이드를 바꿀 때마다 화면 크기 비트맵 하나와 복제본 하나가 만들어지는 것은 맞지만, 이 PC에서는 GC가 거의 매번 돌아 곧 정리된다. 수정 뒤에는 복제본이 없고 바뀐 그림은 바로 해제된다. 메모리 수치로는 차이가 보이지 않는다.
- **슬라이드마다 늘어나는 관리 힙 약 1.5MB**: 강제 GC 뒤에는 넘기기 전과 같다. 쓰레기이지 누수가 아니다.
- **종료 메시지의 구분**: WinForms는 종료가 취소된 뒤에도 창의 닫기 이유를 `WindowsShutDown`으로 남겨 둔다. 그래서 닫기 이유가 아니라 "지금 `WM_QUERYENDSESSION`을 처리하는 중인가"로 묻는 단계를 구분한다 (두 창의 `WndProc`).
- **모달 쇼**: WinForms는 묻는 단계에서 모달 창을 끝낸다. 송출 창이 모달일 때는 묻는 메시지에 직접 "예"로 답하고 창을 그대로 둔다.
- **확정된 종료에서의 순서**: 후킹 해제와 설정 저장을 먼저 하고, 쇼 끝내기와 PowerPoint 정리를 그 뒤에 한다. 평소 닫기의 순서는 그대로다.
- **참조 표시의 빈 상자**: 검증 중 참조 표시 버튼을 누르면 글자 없는 흰 상자가 나오는 것을 봤다. 버그가 아니다. 이 PC의 참조 표시 설정은 원본이 "없음"이고, 버튼은 그때 빈칸 하나를 "활성 표시"로 보낸다 (기존 동작, 수정 전 빌드도 같다). 원본을 제목으로 바꿔 보면(메모리에서만) 글자가 20초 동안 정상으로 보인다.
- **`SaveShowOptions`**: 모달 쇼 뒤의 예배 목록 저장은 이 값이 참일 때만 하는데, 이 값을 참으로 만드는 코드가 없다. 그 저장은 원래도 실행되지 않았다.

보류한 내장 코드 리뷰 지적 (동작에 영향 없음): 한 번만 쓰는 도우미 클래스 둘(`LineFontFamily`, `UnstoredImageGuard`), `Go`에 남은 중복 해제 호출.

## Known Limitations

- **Windows가 실제로 종료될 때 앱은 PowerPoint를 닫지 못한다.** 종료 메시지를 처리하는 동안에는 다른 프로그램을 부르는 호출이 바로 실패한다 (`RPC_E_CANTCALLOUT_ININPUTSYNCCALL`). 수정 전에도 같은 정리를 같은 조건에서 시도했다. PowerPoint는 Windows가 끝낸다. 작업 표시줄과 화면 보호기 복원, 설정 저장은 실행된다.
- 취소된 Windows 종료 뒤에는 닫기 이유가 `WindowsShutDown`으로 남는다 (WinForms). 기록에 그 이유가 찍혀도 실제 종료가 아닐 수 있다.
- 모달 쇼의 종료 경로에서 `FormClosingCleanup`이 두 번 실행될 수 있다. 두 번 실행해도 결과는 같다.
- 모양 전환에서 알림과 참조 글자를 프레임마다 두 번 그린다 (원 전환 등의 기존 동작과 같다). 깜빡임 횟수가 그만큼 빨리 준다.
- 전환 효과는 이 PC의 설정이 "없음"이라 평소 실행으로는 보이지 않는다. 확인은 임시 스위치로 전환 종류를 정해 놓고 했다.
