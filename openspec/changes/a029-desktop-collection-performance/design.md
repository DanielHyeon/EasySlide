# 설계

포맷 정보를 순회하며 최적 후보만 유지한다. 미리보기 목록은 실제 크기와 뷰포트를 따른다. 대량 검색은 DB 리더에서 결과를 제한하고 WPF로 마지막 검색 결과만 전달한다. 키 조회는 기존 비교 규칙을 따르고 저장은 버퍼를 재사용한다. 코드 스타일 변환은 소스 생성기와 호환성을 빌드와 두 앱 회귀 테스트로 확인한다.

## 동작 및 호환성

- 카메라 포맷은 드라이버가 제공한 크기로 읽고 가장 높은 해상도 높이를 선택한다. 높이가 같으면 정확한 4:3 포맷을 우선한다. 후보별 미디어 타입과 포맷 버퍼는 선택·실패 경로 모두에서 해제한다.
- WinForms 파일 목록은 전체 경로를 보관하고 화면에 보이는 행과 다음 한 행만 컨트롤을 사용한다. OfficeLib의 공개 `ScreenDumpFullPath`는 기존 2차원 인덱싱을 유지하며 현재 목록 크기로 교체한다. 구형 CD는 목차 행에서 읽은 양의 곡 번호로 제목을 찾고 중복 번호는 마지막 제목을 사용한다.
- WPF 성경 검색은 조건에 맞는 구절을 한도보다 한 건 더 읽으면 종료한다. 검색어·권·모드가 바뀌면 이전 요청을 취소하고 최신 요청만 화면을 갱신한다.
- 찬양집과 곡 가져오기는 기존 제목 비교 및 중복 선택 순서를 유지한다. 문서 내보내기는 필요한 ID를 묶어 조회한다. WinForms 미디어는 제목 존재 확인에는 대소문자를 무시하고 저장 경로 결정에는 정확한 제목과 기존 확장자 우선순위를 사용한다.
- 프레임 버퍼, 글자 획수 조회 테이블, 파일 포맷 헤더처럼 인덱스 자체가 의미를 갖는 배열은 유지한다.

## 격리 환경 성능 측정

Windows x64, .NET 11 Release에서 임시 파일·DB와 같은 입력을 사용했다. 4회 예열 후 7개 라운드에서 호출당 중앙값을 구했다. 할당량은 측정 스레드의 관리 힙 기준이다.

| 연산 | 수정 전 시간 | 수정 후 시간 | 수정 전 할당 | 수정 후 할당 |
|---|---:|---:|---:|---:|
| HTML 가사 태그 제거, UTF-16 4,864자 | 154.79 µs | 27.57 µs | 1,678,360 B | 15,992 B |
| 10,000곡 중 마지막 곡의 인덱스 조회 | 66.59 µs | 38.97 µs | 80,112 B | 0 B |
| 이미지 4 MiB + 1 B를 XML로 내보내기 | 2.885 ms | 2.135 ms | 4,203,432 B | 9,024 B |
| 성경 30,000행에서 앞쪽 10건 검색 | 43.848 ms | 0.554 ms | 5,121,128 B | 36,888 B |

성경 검색어가 드물면 결과 한도에 도달할 때까지 더 많은 행을 읽는다.
