# Tasks: 예배 순서 목록의 끌어다 놓기

구현 → 적대적 리뷰 → 내장 코드 리뷰 → 총괄 검증 → 커밋.
구현 2회, 적대적 리뷰 1회, 내장 코드 리뷰 1회(지적 3건: 2건 반영, 1건 보류)를 거쳤다.

## 1. 먼저 확인할 것

- [x] 1.1 시험용 목록으로 앱을 띄우는 절차가 실제 목록과 설정을 건드리지 않는지. 저장은 언제나 "지금 고른 목록"의 파일에만 쓴다. 시작할 때 그 목록을 한 번 다시 쓴다(내용은 같다). 레지스트리에는 현재 목록 이름과, 닫을 때 창 상태와 설정을 쓴다
- [x] 1.2 수정 전 빌드에서 사고의 재현. 클릭 30번으로는 재현되지 않았다. 첫 줄을 자기 줄의 맨 아래 픽셀 줄에 놓으면 맨 끝(21/21)으로 가고 바로 저장됐다 (사고와 같은 결과)
- [x] 1.3 `DragOver`가 적는 값은 놓을 줄의 노란 표시에 쓰인다. 새 모양의 목록 그리기도 그 표시를 따른다
- [x] 1.4 다른 목록의 `ItemDrag`가 넘기는 선택 항목은 결과에 영향이 없다 (받는 쪽이 자기 목록을 읽는다). 넘기는 값은 맞췄다

## 2. 구현

- [x] 2.1 W1: 놓는 위치를 놓은 좌표에서 구한다. 줄은 높이로만 찾는다
- [x] 2.2 W2: 순서가 바뀌지 않는 놓기는 아무것도 하지 않는다
- [x] 2.3 W3: 끄는 동안의 값 정리. 놓을 수 없는 자리에서는 커서가 "놓기 금지"가 된다
- [x] 2.4 W5: 다른 목록에서 끌 때 그 목록의 선택 항목을 넘긴다
- [x] 2.5 (리뷰) 그림 파일을 놓을 자리를 알 수 없으면 아무것도 하지 않는다. 한 줄에 놓으면 그 줄에만 적용한다
- [x] 2.6 (리뷰) 옮기다 하나라도 실패하면 전부 되돌리고 저장하지 않는다
- [x] 2.7 (리뷰) 끌기가 끝나면 끌기 출처 표시를 지운다

## 3. 확인 (모두 시험용 목록 `99.TEST-DELETE-ME`에서, 구현 에이전트)

- [x] 3.1 클릭 20번, 짧은 끌기, 빠른 끌기, 자기 줄의 맨 아래 픽셀 줄에 놓기: 목록 파일이 바뀌지 않는다 (해시와 수정 시각)
- [x] 3.2 줄을 다른 줄 위에 놓으면 그 줄 앞에 들어가고 저장된다. 줄 옆의 빈 곳(같은 높이)에 놓아도 같다
- [x] 3.3 끌던 줄 위, 바로 다음 줄 위에 놓으면 파일이 다시 쓰이지 않고 미리보기 표시가 그대로다
- [x] 3.4 마지막 줄 아래에 놓으면 맨 끝으로 간다. 목록의 위쪽 테두리에 놓으면 아무 일도 없다
- [x] 3.5 두 줄을 골라 끌기, 찬양 목록에서 끌어 넣기, Delete 키, 위아래 옮기기 버튼이 수정 전과 같다 (Delete와 버튼은 두 빌드의 결과 해시가 단계마다 같다)
- [x] 3.6 그림 파일과 글 파일을 놓는 경로 (탐색기에서 끌 수 없어, 놓기 처리를 직접 부르는 임시 코드로 확인한 뒤 지웠다): 한 줄에 놓은 그림은 그 줄의 서식만 바꾼다. 자리 없는 곳에서는 아무 일도 없다
- [x] 3.7 실제 목록 32개의 해시와 레지스트리가 시험 전과 같다. 시험용 목록은 지웠다 (구현 에이전트와 총괄이 각각 확인)

## 확인 못 한 것

- 사고의 정확한 경로("끄는 동안의 값이 한 번도 적히지 않은 채 놓임")는 만들어 내지 못했다. 같은 결과를 내는 다른 경로(맨 아래 픽셀 줄)로 재현했다.
- 옮기다 실패하는 경우(2.6)는 실행으로 만들 수 없어 코드로만 확인했다.
- 탐색기에서 실제로 파일을 끌어다 놓는 것, 성경 구절을 끌어다 놓는 것.
- 쇼 진행 중의 끌어다 놓기와 송출 줄 표시.
