## Context

메뉴와 도구 모음의 Options는 SettingsWindow를 연다. 기존 CameraOwnership이 WPF 송출과 OBS 카메라 모드를 조율하고 DirectShowVideo가 장치 그래프와 프레임 버퍼를 소유한다. CodeGraph 인덱스에서 해당 WPF 심볼이 조회되지 않아 소스 호출 경로와 기존 카메라 테스트를 확인했다.

## Goals / Non-Goals

운영자에게 장치 목록, 실제 카메라 프레임, 마이크의 기본 장치 여부·음소거·입력 레벨을 제공한다. 점검은 로컬 모니터링으로 한정한다.

## Decisions

- 설정 창의 새 탭에서만 장치를 열거한다. 목록은 장치 이름과 안정적인 장치 경로 또는 엔드포인트 ID를 함께 유지한다. 실제 앱 테마에서도 탭 목록을 왼쪽에 두고, 카메라 오른쪽에 마이크와 OBS 상태를 배치한다.
- 로컬 카메라는 기존 DirectShow 워커를 사용한다. 점검 전용 소유권은 실제 송출 요청에 양보한다. 기존 영상이 있을 때 점검 화면은 이 영상을 재사용한다.
- 마이크는 NAudio.Wasapi의 공유 모드 입력 스트림에서 Windows 엔드포인트의 음소거와 피크를 확인한다. 장치 I/O는 작업 스레드에서 수행하고 화면에는 수치와 상태만 전달한다.
- 장치 변경, 목록 갱신, 탭 이탈, 창 닫기에서 점검을 중단한다. 이전 점검의 비동기 결과는 화면에 반영하지 않는다.

- OBS 제어 연결 이벤트를 구독해 현재 상태와 프로그램 씬을 표시한다. 연결 확인은 별도 WebSocket에서 인증 후 GetCurrentProgramScene 요청만 보내고 종료한다. 프로그램 씬과 최근 점검 결과를 구분하고 일회성 암호는 저장하지 않는다.

## Risks / Trade-offs

접근 권한·장치 점유·드라이버에 따라 목록에 있는 장치도 열리지 않을 수 있다. 마이크 레벨은 Windows 입력 신호이며 OBS 필터와 믹서의 후처리 레벨은 별도다.
