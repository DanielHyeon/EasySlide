# Tasks: PPT 슬라이드 쇼가 출력 모니터의 다른 창 뒤에 뜨는 문제 수정

구현 → 적대적 리뷰 → 내장 코드 리뷰 → 총괄 검증 → 커밋.

## 1. 먼저 확인할 것

- [x] 1.1 문제 상태에서 창 순서를 덤프한다 (출력 모니터의 창들: 클래스, 제목, "항상 위" 여부, 소유 창, 위아래 순서). 슬라이드 쇼 창이 "항상 위"가 아니고 다른 앱의 창 아래에 있다는 추론을 확인한다
- [x] 1.2 메인 화면 쪽의 두 번째 `Run`(`MainPPT`)이 창 순서에 주는 영향을 확인한다

## 2. 구현

- [x] 2.1 Z1: `Run` 뒤에 슬라이드 쇼 창을 "항상 위"로 올린다 (포커스를 옮기지 않는다). `SetShowWindow` 뒤에도 올린다. `Run`의 두 형태 모두
- [x] 2.2 Z2: 송출 창이 슬라이드 쇼 위에 남게 한다
- [x] 2.3 Z3: 쇼를 끝낼 때 올려 둔 창의 "항상 위"를 푼다
- [x] 2.4 Z4: 모니터 둘 방식의 쇼에만 적용한다
- [x] 2.5 Z5: 실패하면 기록하고 알림 칸에 알린다

## 4. 리뷰 반영

- [x] 4.1 Z6: 슬라이드 쇼 창이 출력 모니터에 있을 때만 올린다. 아니면 알린다
- [x] 4.2 Z7: PPT가 아닌 항목이 송출되면 올려 둔 슬라이드 쇼를 내린다 (송출 창이 새 항목을 그린 뒤)
- [x] 4.3 Z8: 앱 시작과 쇼 시작 때 남아 있는 "항상 위" 슬라이드 쇼를 내린다
- [x] 4.4 이미 "항상 위"인 창에는 해제를 보내지 않는다. `SetShowWindow` 뒤에는 찾아 둔 핸들을 다시 쓴다
- [x] 4.5 창 찾기: 짧은 재시도, "구분선 + 이름" 비교
- [x] 4.6 실패 알림은 항목당 한 번. 내릴 때는 응답을 기다리지 않는다. `Run(int)`에 더한 코드를 뺀다

## 5. 2차 리뷰와 코드 리뷰 반영

- [x] 5.1 Z9: 쇼 도중의 내리기는 기다린다. PPT 항목을 불러오기 시작할 때 대기 중인 내리기를 취소한다
- [x] 5.2 같은 모니터 설정에서는 알리지 않는다. 되돌리기는 운영자의 모니터에 있을 때만
- [x] 5.3 알림: 한 번이라도 올렸으면 알리지 않는다. 예약이 유실돼도 다음 알림이 막히지 않는다
- [x] 5.4 창 찾기 비용을 줄인다. 느슨한 제목 비교는 마지막 시도에서만
- [x] 5.5 타이머 정리, 간격 항목 경로, 앱 시작 때의 호출 위치, 중복 선언
- [x] 5.6 PPT 항목의 슬라이드 쇼가 시작되지 못하면 올려 둔 슬라이드 쇼를 내리고 알린다 (이전 항목의 슬라이드가 맨 위에 남지 않게)
- [x] 5.7 창 핸들 읽기를 포기하는 조건을 관찰한 오류(DISP_E_MEMBERNOTFOUND)로 한정한다

## 3. 확인 (출력 모니터에 다른 앱의 창을 최대화해 둔 상태)

- [x] 3.1 PPT 항목을 송출로 보내면 슬라이드가 출력 모니터에 보인다. 쇼 시작 때 첫 항목이 PPT인 경우도 같다
- [x] 3.2 메인 화면이 포커스를 유지한다 (송출 뒤 메인 화면에서 키 입력이 된다)
- [x] 3.3 PPT → 가사 → PPT, PPT A → PPT B: 매번 맞는 내용이 맨 위에 보인다
- [ ] 3.4 PPT 항목 위에 알림, 참조 표시가 보인다
- [x] 3.5 쇼를 끝내면 출력 모니터에 "항상 위" 창이 남지 않는다. 다시 시작해도 같다
- [ ] 3.6 앱이 전경이 아닐 때 항목이 바뀌어도 슬라이드가 보인다
- [x] 3.7 수정 전 빌드와 비교한 캡처

## 6. 확인 못 한 것

- 3.4 PPT 항목 위의 알림, 참조 표시: 기존 코드가 PPT 항목에서는 참조 표시를 그리지 않고, 알림은 안전하게 켤 방법이 없었다. 송출 창이 슬라이드 쇼 위에 있다는 창 순서만 확인했다
- 3.6 앱이 전경이 아닐 때의 송출: 부분적으로만 확인했다 (전경이 아닌 프로세스에서 같은 호출이 적용되는 것은 별도 프로그램으로 확인)
- 자동 넘김으로 항목이 바뀌는 순서, 비디오 항목, 간격 항목, 사용자 지정 출력 영역, 모니터 하나 방식: 앱에서 실행하지 못했다
- 전환 효과가 있는 가사 항목 뒤의 내리기 (이 PC의 전환 설정이 "없음")
- PowerPoint가 응답 없는 상태, 올리기 실패 알림이 실제로 뜨는 것
- 다른 버전의 PowerPoint (창 핸들 읽기와 "항상 위" 적용 방식은 이 PC의 PowerPoint 16에서 실험으로 찾았다)
