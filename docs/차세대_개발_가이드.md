# 차세대 EasiSlides 개발 가이드 (WinUI 3 · 4중 모니터 · OBS)

작성일: 2026-11-14 · 원본 문서: <https://claude.ai/artifact/4DwjPPEFxCvJguWNCj9CjN>

## 1. 점검 요약

원 가이드의 큰 방향은 유지합니다. PNG 사전 추출, 모니터별 독립 창, `MediaPlayerElement` 사용은 그대로 둡니다. 다만 사실과 다른 내용 6가지를 고쳤고, PPT 애니메이션·동영상 처리와 프로세스 분리 2가지를 새로 넣었습니다.

| 항목 | 원 가이드의 주장 | 점검 결과 | 이 문서의 처리 |
| --- | --- | --- | --- |
| Native AOT와 Office Interop | 한 앱 안에서 함께 사용 | 불가. Native AOT는 Windows의 기본 제공 COM을 지원하지 않습니다 ([Native AOT 제한 사항](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/)) | Office 작업을 별도 프로세스로 분리 (2장) |
| PPT 처리 | 모든 슬라이드를 PNG로 추출 | 애니메이션, 전환 효과, 내장 동영상·오디오가 모두 사라집니다 | 슬라이드별 3등급 렌더링 (4장) |
| `runtime-async=on` | 성능을 크게 올리는 핵심 설정 | .NET 11은 2026-11-10 정식 출시됐고, 이 설정은 여전히 선택 사항입니다. Native AOT에서도 동작합니다. 주된 효과는 깔끔한 스택 추적과 낮은 비동기 오버헤드입니다 ([.NET 11 런타임](https://learn.microsoft.com/en-us/dotnet/core/whats-new/dotnet-11/runtime)) | 유지하되 선택 사항으로 표기 |
| 메모리와 전환 속도 | 메모리 수 KB, 전환 0ms | 4K 비트맵 1장은 디코드하면 약 33MB입니다 (3840 × 2160 × 4바이트). 3장이면 약 100MB입니다. 전환은 화면 한 프레임(60Hz에서 약 16ms)이 하한입니다 | 목표 수치를 다시 설정 (6장) |
| 앱 RAM | 50~100MB | 4K 비트맵 3장만으로 100MB입니다. 창 4개와 동영상을 더하면 넘습니다 | 실측 기준 목표로 교체 (6장) |
| 동영상 가속 | DirectX 12 직접 사용 | `MediaPlayerElement`는 Windows 미디어 스택의 스왑 체인을 그대로 화면에 넘깁니다. DirectX 버전은 앱이 정하지 않습니다 ([Visual layer 문서](https://learn.microsoft.com/en-us/windows/apps/develop/composition/visual-layer)) | "GPU 하드웨어 디코딩"으로 표현 수정 |
| 영상 위 자막 | `TextBlock`을 겹치면 됨 | 맞습니다. 단, 영상 **뒤**에 XAML 콘텐츠를 두거나 영상을 흐리게(블러) 처리하는 것은 불가합니다 (같은 문서) | 유지, 제약을 명시 (5장) |
| 개발 기간 | 수 주 내 완성 | 성경, 가사 DB, 예배 순서, 단축키 등 기존 EasiSlides 기능 이식은 포함되지 않은 추정입니다 | 단계별 계획으로 교체 (8장) |

## 2. 기술 스택과 프로세스 구조

앱을 두 프로세스로 나눕니다. 화면을 그리는 메인 앱은 Native AOT로 빌드하고, PowerPoint를 다루는 OfficeBridge는 일반 .NET(JIT)으로 빌드합니다. Native AOT가 COM을 지원하지 않기 때문에 이 분리는 선택이 아니라 필수입니다.

```text
+--------------------------------------------+               +-----------------------------+
| 메인 앱 · WinUI 3, Native AOT              |  named pipe   | OfficeBridge · 일반 .NET    |
| 창 4개, 이미지·동영상·자막 렌더링,         | <-----------> | PPT 분석, PNG 추출          |
| 예배 순서, DB. COM 코드를 넣지 않음        |               | 슬라이드쇼 제어             |
+--------------------------------------------+               +-----------------------------+
     |          |           |          |                                   | COM
     v          v           v          v                                   v
 [조종관]  [프로젝터]  [프롬프터]  [OBS 자막]                    [PowerPoint (POWERPNT.EXE)]
               ^                                                           |
               +- - - 라이브 등급일 때만: 슬라이드쇼 창이 직접 덮음 - - - -+
```

PowerPoint가 멈추거나 죽어도 영향은 OfficeBridge까지만 갑니다. 메인 앱의 창 4개는 계속 화면을 그립니다.

| 프로세스 | 빌드 방식 | 맡는 일 | 죽었을 때 |
| --- | --- | --- | --- |
| 메인 앱 (`EasiSlides.exe`) | WinUI 3, Native AOT | 창 4개, 이미지·동영상·자막 렌더링, 예배 순서, DB | 송출 중단. 그래서 여기에는 COM을 넣지 않습니다 |
| OfficeBridge (`OfficeBridge.exe`) | 콘솔 앱, 일반 .NET 11 | PPT 분석, PNG 추출, 슬라이드쇼 제어, Word·Excel 변환 | 메인 앱이 남은 PowerPoint 프로세스를 정리하고 다시 띄웁니다. 이미 추출한 PNG 송출은 계속됩니다 |

### 통신

- 두 프로세스는 named pipe로 메시지를 주고받습니다. 메시지 직렬화는 `System.Text.Json` 소스 생성기를 씁니다.
- 메시지 타입은 두 프로세스가 함께 참조하는 공용 라이브러리(`EasiSlides.Contracts`)에 둡니다. 이 라이브러리에만 `IsAotCompatible`을 켭니다.
- OfficeBridge는 자기가 띄운 `POWERPNT.EXE`의 프로세스 ID를 메인 앱에 알립니다. 브리지가 응답하지 않으면 메인 앱이 그 ID만 종료합니다. 사용자가 따로 열어 둔 PowerPoint는 건드리지 않습니다.

### 메인 앱 프로젝트 파일

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>WinExe</OutputType>
    <TargetFramework>net11.0-windows10.0.19041.0</TargetFramework>
    <TargetPlatformMinVersion>10.0.17763.0</TargetPlatformMinVersion>
    <UseWinUI>true</UseWinUI>
    <Platforms>x64;ARM64</Platforms>
    <RuntimeIdentifiers>win-x64;win-arm64</RuntimeIdentifiers>

    <!-- No JIT at run time. Also turns on the trim/AOT analyzers for this app. -->
    <PublishAot>true</PublishAot>

    <!-- Optional. Remove this line if a dependency misbehaves. -->
    <Features>runtime-async=on</Features>
  </PropertyGroup>

  <ItemGroup>
    <PackageReference Include="Microsoft.WindowsAppSDK" Version="(latest stable)" />
  </ItemGroup>
</Project>
```

원 가이드와 달라진 점은 세 가지입니다.

- `IsAotCompatible`을 뺐습니다. 이 속성은 라이브러리용이고, 앱은 `PublishAot`만으로 분석기가 켜집니다.
- `Platforms`와 `RuntimeIdentifiers`를 넣었습니다. Native AOT는 대상 CPU를 정해야 게시할 수 있습니다.
- 빌드 PC에 Visual Studio의 "C++를 사용한 데스크톱 개발" 워크로드가 필요합니다.

### Native AOT에서 지킬 코딩 규칙

- XAML 바인딩은 `{x:Bind}`만 씁니다. `{Binding}`은 런타임 리플렉션에 의존합니다.
- JSON은 `JsonSerializerContext` 소스 생성기를 씁니다.
- MVVM은 CommunityToolkit.Mvvm의 소스 생성기(`[ObservableProperty]`, `[RelayCommand]`)를 씁니다.
- NuGet 패키지를 추가할 때마다 AOT 경고가 0개인지 확인합니다. Windows App SDK는 1.6부터 `PublishAot`을 지원하지만, 의존 패키지가 AOT를 지원하지 않으면 실행 중에 문제가 납니다 ([Windows App SDK 1.6 릴리스 노트](https://learn.microsoft.com/en-us/windows/apps/windows-app-sdk/release-notes/windows-app-sdk-1-6)).

### 전제 조건

방송실 PC에 PowerPoint가 설치돼 있어야 합니다. 설치돼 있지 않으면 PPT 가져오기 기능만 꺼지고, 가사·성경·이미지·동영상 송출은 그대로 동작하게 만듭니다.

## 3. 4중 모니터 창 배치

모니터마다 독립된 창을 하나씩 띄우고, 어느 모니터가 어떤 역할인지는 사용자가 설정에서 지정합니다. 원 가이드처럼 "0번은 조종관, 1번은 프로젝터"로 번호를 고정하면 안 됩니다. 재부팅하거나 케이블을 다시 꽂으면 번호 순서가 바뀝니다.

| 역할 | 보여 주는 것 | 렌더링 규칙 |
| --- | --- | --- |
| 조종관 | 컨트롤러, 예배 순서, 썸네일 미리보기 | 일반 창. 썸네일은 `Stretch="Uniform"`, 디코드 폭은 320 × 화면 배율 (150%면 480) |
| 본당 프로젝터 | 슬라이드, 가사, 동영상 | 테두리 없는 전체 화면. 디코드 폭은 그 모니터의 실제 픽셀 폭 (1080p 프로젝터면 1920) |
| 강단 프롬프터 | 현재 가사, 다음 가사, 설교 요약, 시계 | 검은 배경에 `TextBlock`만 사용. 이미지와 동영상은 올리지 않음 |
| OBS 중계 | 하단 자막 | 녹색(#00FF00) 배경 위에 자막만 표시 (5장) |

### 구현 규칙

1. **모니터 찾기.** `DisplayArea.FindAll()`로 목록을 얻습니다. `foreach` 대신 인덱스 `for` 문으로 돌립니다. 일부 SDK 버전에서 `foreach`가 예외를 낸 적이 있습니다.
2. **역할 저장.** 역할은 모니터의 장치 식별자와 함께 저장합니다. 식별자가 맞는 모니터가 없으면 해상도와 위치가 같은 모니터를 찾고, 그것도 없으면 사용자에게 묻습니다.
3. **모니터 수가 모자랄 때.** 모니터가 없는 역할의 창은 만들지 않습니다. 현재 EasiSlides의 규칙(싱글 모드는 주 모니터, 수동 영역 지정, `None`은 송출 안 함)을 그대로 옮깁니다.
4. **연결 변경.** `DisplayArea.CreateWatcher()`로 모니터 추가·제거를 감시합니다. 프로젝터 전원이 꺼졌다 켜져도 창이 제자리로 돌아와야 합니다.
5. **전체 화면.** `AppWindow.Move()`로 대상 모니터의 좌표로 옮긴 다음 `SetPresenter(AppWindowPresenterKind.FullScreen)`을 호출합니다. 순서가 바뀌면 엉뚱한 모니터가 전체 화면이 됩니다.
6. **배율 차이.** 송출 창의 내용은 1920 × 1080 고정 캔버스에 배치하고 `Viewbox`로 감쌉니다. 모니터마다 Windows 배율이 달라도 글자 크기와 줄바꿈이 같아집니다.
7. **포커스.** 송출 창은 클릭해도 활성화되지 않게 하고 마우스 커서를 숨깁니다. 키보드 입력은 항상 조종관 창이 받습니다.
8. **절전 방지.** 송출 중에는 화면 꺼짐과 화면 보호기를 막습니다.
9. **이미지 로드.** `BitmapImage.DecodePixelWidth`는 `UriSource`보다 먼저 설정합니다. 나중에 설정하면 원본 크기로 디코드됩니다.

창 4개는 기본적으로 하나의 UI 스레드를 함께 씁니다. 조종관에서 무거운 작업을 UI 스레드로 하면 송출 화면 전환도 같이 멈춥니다. 파일 읽기, DB 조회, OfficeBridge 호출은 모두 백그라운드로 보냅니다.

## 4. PPT 렌더 파이프라인

PPT를 불러올 때 슬라이드마다 내용을 분석해서 세 등급 중 하나로 분류하고, 등급에 따라 다른 방식으로 송출합니다. 정적인 슬라이드는 원 가이드대로 PNG로 처리하고, 애니메이션과 동영상이 있는 슬라이드만 다르게 다룹니다.

| 등급 | 해당하는 슬라이드 | 송출 방식 | 애니메이션 재현 정도 |
| --- | --- | --- | --- |
| 정적 | 애니메이션도 미디어도 없음 | PNG 1장 | 해당 없음 |
| 단계형 | 클릭할 때마다 나타나거나 사라지는 효과, 또는 사각형 동영상 | 클릭 단계별 PNG + 동영상 오버레이 | 나타나는 순서는 유지. 효과 종류는 모두 페이드로 통일 |
| 라이브 | 이동 경로, 강조 효과, 트리거, 모핑 전환, 여러 슬라이드에 걸친 오디오, 동영상 위에 겹친 도형 | 실제 PowerPoint 슬라이드쇼를 프로젝터 모니터에 띄움 | 원본 그대로 |

사용자는 파일 단위로 등급을 강제할 수 있어야 합니다. 예를 들어 "이 파일은 항상 PowerPoint로 재생"을 고를 수 있게 합니다. 자동 분류가 틀렸을 때 현장에서 바로 대처하는 수단입니다.

### 4.1 분석 (OfficeBridge)

슬라이드마다 아래 값을 읽어 메인 앱에 넘깁니다.

- `TimeLine.MainSequence`: 효과 목록. 효과마다 시작 방식(클릭 / 이전 효과와 함께 / 이전 효과 다음), 나타내기인지 끝내기인지, 대상 도형과 문단
- `TimeLine.InteractiveSequences`: 트리거가 있는지
- 도형 중 `Type == msoMedia`인 것: 동영상과 오디오
- `SlideShowTransition`: 전환 효과 종류, 길이, 자동 넘김 시간
- 슬라이드 노트 텍스트: 강단 프롬프터에 표시

### 4.2 정적 슬라이드

- `Slide.Export`로 PNG를 뽑아 SSD의 캐시 폴더에 저장합니다. 폭은 프로젝터 해상도에 맞춥니다 (1080p면 1920, 4K면 3840).
- 캐시 키는 파일 경로, 수정 시각, 크기입니다. 파일이 안 바뀌었으면 다시 뽑지 않습니다.
- 추출은 백그라운드 큐에서 한 장씩 진행하고, 끝난 슬라이드부터 바로 쓸 수 있게 합니다. 조종관에 진행률을 표시합니다.
- 송출 창에는 `Image` 3개(이전, 현재, 다음)를 겹쳐 두고 `Opacity`만 바꿉니다. 다음 장이 미리 디코드돼 있어서 전환이 한 프레임 안에 끝납니다.

### 4.3 단계형 슬라이드: 클릭 단계별 PNG

클릭으로 시작하는 효과가 N개인 슬라이드는 PNG N+1장으로 만듭니다. "클릭 0번 후의 화면"부터 "클릭 N번 후의 화면"까지입니다.

1. 원본은 건드리지 않고, 임시 폴더에 복사한 파일을 엽니다.
2. 단계 k마다 도형의 표시 여부를 정합니다. 나타내기 효과가 k번 클릭보다 뒤에 있는 도형은 숨기고, 끝내기 효과가 k번 클릭 이하에 있는 도형도 숨깁니다.
3. "이전 효과와 함께", "이전 효과 다음"으로 시작하는 효과는 앞선 클릭과 같은 단계로 묶습니다.
4. 한 텍스트 상자가 문단별로 나타나는 경우, 아직 나오지 않은 문단의 글자를 투명하게 바꿉니다. 도형을 통째로 숨기면 이미 나온 문단도 사라집니다.
5. 단계마다 `Slide.Export`를 호출합니다.

송출할 때 "다음"을 누르면 다음 단계 이미지로 0.2~0.3초 페이드합니다. 가사가 한 줄씩 나타나는 슬라이드와 설교 요점 슬라이드는 이 방식으로 처리됩니다. "날아오기" 같은 움직임은 재현되지 않습니다.

### 4.4 단계형 슬라이드: 내장 동영상

슬라이드 안의 동영상은 파일을 꺼내서 `MediaPlayerElement`로 직접 재생합니다.

1. **파일 꺼내기.** `.pptx`는 zip 파일입니다. 동영상은 `ppt/media/` 폴더에 있고, 어느 도형의 동영상인지는 슬라이드 XML의 관계(`r:embed`, `r:link`)로 찾습니다. 구형 `.ppt`는 먼저 `.pptx`로 저장한 뒤 처리합니다.
2. **위치.** 도형의 `Left`, `Top`, `Width`, `Height`를 슬라이드 크기에 대한 비율로 바꿔 저장합니다. 비율로 저장하면 출력 해상도가 달라도 같은 자리에 놓입니다.
3. **재생 설정.** `MediaFormat`에서 자르기 시작·끝 지점, 음량, 음소거를 읽습니다. `AnimationSettings.PlaySettings`에서 자동 재생 여부와 반복 여부를 읽습니다.
4. **배경.** 동영상 도형을 숨긴 상태로 슬라이드 PNG를 뽑습니다. 그 위 같은 자리에 `MediaPlayerElement`를 놓습니다.
5. **연결된 파일.** 외부 파일로 연결된 동영상은 경로가 유효한지 불러올 때 확인하고, 없으면 조종관에 경고를 띄웁니다.

동영상 위에 다른 도형이 겹쳐 있거나 동영상이 회전·원형으로 잘려 있으면 이 방식으로 맞출 수 없습니다. 그런 슬라이드는 라이브 등급으로 보냅니다.

### 4.5 라이브 슬라이드: 실제 PowerPoint 송출

현재 EasiSlides가 쓰는 방식(`OfficeLib/PowerPoint.cs`의 `SlideShowWindow` 제어)을 OfficeBridge로 옮깁니다.

- PowerPoint 슬라이드쇼 창을 프로젝터 모니터의 좌표에 그대로 띄웁니다. `SetParent`로 앱 창 안에 넣는 방식은 쓰지 않습니다.
- `SlideShowWindow`의 좌표는 픽셀이 아니라 포인트 단위입니다. 모니터 배율에 맞춰 환산해야 합니다.
- 발표자 보기는 끕니다 (`ShowPresenterView = msoFalse`).
- 조종관의 "다음", "이전"은 `View.Next()`, `View.Previous()`, `View.GotoSlide()`로 전달합니다.
- PowerPoint의 `SlideShowNextSlide`, `SlideShowNextClick`, `SlideShowEnd` 이벤트를 받아 조종관 썸네일의 현재 위치를 맞춥니다.
- 라이브 구간에 들어가기 전에 슬라이드쇼를 미리 시작해 송출 창 뒤에 둡니다. 구간에 들어갈 때 창 순서만 바꿉니다. PowerPoint 로딩 화면이 프로젝터에 비치지 않게 하기 위해서입니다.
- 라이브 구간에서도 강단 프롬프터와 OBS 자막 창은 메인 앱이 그립니다.

### 4.6 자동으로 넘어가는 슬라이드: MP4로 미리 변환

클릭 없이 시간에 맞춰 흐르는 광고 슬라이드는 `Presentation.CreateVideo`로 MP4를 만들어 일반 동영상처럼 재생합니다. 애니메이션, 전환, 내장 영상이 모두 녹화됩니다. 변환이 오래 걸리므로 예배 전에 미리 해 둡니다. 클릭으로 진행하는 슬라이드에는 쓸 수 없습니다.

### 4.7 전환 효과

정적·단계형 슬라이드 사이의 전환은 페이드, 밀어내기, 닦아내기, 즉시 전환 네 가지만 앱에서 재현합니다. 그 밖의 효과는 페이드로 바꿉니다.

### 4.8 Word와 Excel

OfficeBridge가 PDF로 내보내고, 메인 앱이 `Windows.Data.Pdf`로 페이지를 PNG로 만듭니다. 이후는 정적 슬라이드와 같은 경로를 탑니다.

## 5. 동영상, 자막, OBS 연동

동영상은 `MediaPlayerElement`로 재생하고, 자막은 그 위에 `TextBlock`을 겹칩니다. 이 조합은 Microsoft 문서로 확인했습니다. 동영상은 앱이 그린 화면 아래에 깔리고, 앱의 화면에는 그 자리만큼 구멍이 뚫립니다. 그래서 영상 위에 올린 글자는 보이지만, 영상 뒤에 둔 XAML 요소는 보이지 않습니다.

### 동영상

- 송출 창의 `MediaPlayerElement`는 재생 컨트롤을 끕니다. 재생, 정지, 위치 이동은 조종관에서만 합니다.
- 조종관에는 재생 위치 막대와 정지 화면만 보여 줍니다. 같은 영상을 두 곳에서 재생하면 소리가 겹치고 GPU를 두 배로 씁니다.
- H.264 영상과 AAC 음성의 MP4를 표준으로 정합니다. HEVC(H.265) 파일은 PC에 확장 코덱이 없으면 재생되지 않습니다. 파일을 불러올 때 열리는지 미리 확인하고, 안 열리면 조종관에 경고합니다.
- 영상을 흐리게 하는 효과(`AcrylicBrush`)는 동영상 위에서 동작하지 않습니다. 자막 배경은 반투명 단색 상자로 만듭니다.

### 오디오 출력 장치

- `MediaPlayer.AudioDevice`에 예배당 믹서로 나가는 장치를 지정합니다. 장치는 설정 화면에서 고르고 저장합니다.
- Windows의 기본 출력 장치는 방송실 PC 스피커로 둡니다. 그러면 알림음은 PC 스피커로, 앱의 영상 소리만 믹서로 나갑니다.
- 저장된 장치가 연결돼 있지 않으면 기본 장치로 조용히 바꾸지 말고 조종관에 경고를 띄웁니다.
- 라이브 등급 슬라이드의 소리는 PowerPoint가 재생하므로 이 설정을 따르지 않습니다. Windows의 "앱별 볼륨 및 장치" 설정에서 PowerPoint의 출력을 믹서로 지정해 둡니다.

### OBS 자막 창

녹색 배경 위에 자막을 그리고 OBS에서 크로마키로 합성하는 방식은 유지합니다. 다만 원 가이드의 "그림자 효과"는 빼야 합니다.

- 부드러운 그림자는 반투명이라 녹색과 섞여 어두운 녹색이 됩니다. OBS가 이 부분을 깔끔하게 지우지 못해 글자 주변에 녹색 테가 남습니다.
- 그림자 대신 불투명한 검은 외곽선(4px 이상)을 쓰거나, 글자 뒤에 불투명한 어두운 띠를 깔아 줍니다.
- 글자는 흰색이나 노란색을 씁니다. 녹색 계열 글자는 같이 지워집니다.
- 자막은 화면 아래 1/3 영역에 최대 2줄, 글자 크기 48 이상으로 둡니다. 본당 프로젝터와 같은 가사 데이터를 쓰되 줄바꿈은 따로 계산합니다.

크로마키 없이 하는 방법도 있습니다. 자막 창을 "불투명한 띠 + 글자"로만 만들고 OBS에서 그 띠 부분만 잘라서 화면 아래에 얹습니다. 색을 지우는 과정이 없어서 글자 가장자리가 가장 깨끗합니다. 자막이 영상 위에 띠 없이 떠 있어야 할 때만 크로마키를 씁니다.

OBS가 화면을 가져가는 방법은 두 가지입니다. 네 번째 모니터가 있으면 "디스플레이 캡처"를 씁니다. 모니터가 모자라면 자막 창을 일반 창으로 띄우고 "창 캡처"를 씁니다. 창 캡처가 다른 창에 가려진 상태에서도 자막을 잡는지는 방송실 PC에서 확인이 필요합니다 (7장).

## 6. 성능과 메모리 목표

원 가이드의 "전환 0ms, 메모리 수 KB, RAM 50~100MB"는 달성할 수 없는 수치입니다. 아래 값을 초기 목표로 잡고, 기술 검증 단계에서 실측한 뒤 조정합니다.

| 항목 | 초기 목표 | 근거 |
| --- | --- | --- |
| 실행부터 조종관 창 표시까지 | 1초 이내 | Native AOT는 JIT 컴파일 단계가 없습니다 |
| 슬라이드 전환 (다음 장이 미리 디코드된 상태) | 2프레임 이내 (60Hz에서 약 33ms) | `Opacity`만 바꾸므로 디코딩이 없습니다 |
| 슬라이드 비트맵 메모리, 1080p 출력 | 약 25MB | 1920 × 1080 × 4바이트 = 8.3MB, 3장 |
| 슬라이드 비트맵 메모리, 4K 출력 | 약 100MB | 3840 × 2160 × 4바이트 = 33MB, 3장 |
| PNG 추출 시간 | 슬라이드당 수백 ms~수 초 (현재와 같음) | PowerPoint의 내보내기 속도는 앱이 바꿀 수 없습니다 |
| PNG 추출 중 조종관 반응 | 멈춤 없음 | 추출이 다른 프로세스에서 진행됩니다 |

PNG 추출 속도 자체는 빨라지지 않습니다. 달라지는 것은 추출 중에도 조종관이 멈추지 않는다는 점과, 한 번 뽑은 파일은 캐시에서 바로 나온다는 점입니다. 현재 EasiSlides의 가장 큰 병목인 동기 내보내기 문제가 이것으로 해결됩니다.

## 7. 먼저 검증할 항목

아래 9가지는 문서만으로 확정할 수 없어서, 본 개발 전에 작은 시험 앱으로 확인해야 합니다. 하나라도 실패하면 해당 부분의 설계를 바꿉니다.

| 확인할 것 | 왜 불확실한가 | 실패하면 |
| --- | --- | --- |
| Windows App SDK가 `net11.0` + `PublishAot`에서 빌드되고 창 4개가 뜨는가 | .NET 11은 2026-11-10에 나온 새 버전입니다 | `net10.0`으로 시작하고 나중에 올립니다 |
| `runtime-async=on`을 켠 상태에서 WinRT 비동기 API가 정상 동작하는가 | 새 기능이고 선택 사항입니다 | 이 설정을 끕니다 |
| SQLite 라이브러리가 AOT에서 경고 없이 동작하는가 | 현재 쓰는 `System.Data.SQLite.Core`의 AOT 호환성을 확인하지 못했습니다 | `Microsoft.Data.Sqlite`로 바꿉니다 |
| MariaDB 동기화 라이브러리가 AOT에서 동작하는가 | `MySqlConnector`의 AOT 호환성을 확인하지 못했습니다 | 동기화를 OfficeBridge처럼 별도 프로세스로 분리합니다 |
| PowerPoint 슬라이드쇼 창이 배율이 다른 모니터에서 정확한 자리에 뜨는가 | 좌표가 포인트 단위이고 환산 기준이 모니터마다 다를 수 있습니다 | 창을 띄운 뒤 Win32 `SetWindowPos`로 픽셀 좌표를 다시 맞춥니다 |
| 송출 창과 PowerPoint 창의 순서를 바꿀 때 깜빡임이 없는가 | 두 프로세스의 창이 같은 모니터를 덮습니다 | 전환 순간에 검은 화면을 한 프레임 끼웁니다 |
| 단계별 PNG가 실제 슬라이드쇼와 같은 화면인가 | 문단 단위 효과와 끝내기 효과의 조합이 다양합니다 | 틀린 유형을 라이브 등급으로 분류합니다 |
| OBS 창 캡처가 가려진 자막 창을 잡는가 | OBS 버전과 캡처 방식에 따라 다릅니다 | 네 번째 모니터나 HDMI 더미 플러그를 씁니다 |
| 전역 키보드 후킹(리모컨 단축키)이 AOT에서 동작하는가 | 현재 `HookManager`는 델리게이트 마셜링을 씁니다 | `LibraryImport`와 함수 포인터 콜백으로 다시 작성합니다 |

단계별 PNG의 정확도는 교회에서 실제로 쓴 PPT 파일 20개 이상으로 비교합니다. 시험용으로 만든 파일만으로는 현장에서 쓰는 효과 조합을 다 담지 못합니다.

## 8. 개발 단계

개발은 7단계로 나누고, 단계마다 통과 기준을 둡니다. 기간은 적지 않았습니다. 1단계(기술 검증)가 끝나야 추정할 수 있습니다. 현재 EasiSlides v2.6.3은 새 앱이 6단계를 통과할 때까지 예배에서 계속 사용합니다.

1. **기술 검증.** 7장의 9가지를 시험 앱으로 확인합니다.
   - 통과 기준: AOT로 빌드한 앱이 창 4개를 띄우고, OfficeBridge가 PNG 1장을 뽑아 그 창에 표시합니다.
2. **창과 모니터.** 모니터 관리자, 역할 설정 화면, 창 4개의 생성과 복구를 만듭니다.
   - 통과 기준: 프로젝터 케이블을 뽑았다 꽂아도 창이 제자리로 돌아옵니다.
3. **가사·성경·이미지 송출.** 기존 SQLite DB를 읽어 예배 순서대로 송출합니다. 강단 프롬프터와 OBS 자막 창을 함께 만듭니다.
   - 통과 기준: PPT 없는 예배 순서 하나를 처음부터 끝까지 진행합니다.
4. **동영상.** 재생, 오디오 장치 지정, 영상 위 자막을 만듭니다.
   - 통과 기준: 4K 영상을 재생하는 동안 조종관 조작이 끊기지 않습니다.
5. **PPT 정적·단계형.** 분석, PNG 추출, 캐시, 단계별 PNG, 내장 동영상을 만듭니다.
   - 통과 기준: 실제 교회 PPT 20개 중 단계형으로 분류된 슬라이드가 PowerPoint 화면과 일치합니다.
6. **PPT 라이브.** 실제 슬라이드쇼 송출, 조종관 동기화, MP4 변환을 만듭니다.
   - 통과 기준: 실제 예배 순서로 리허설을 2회 진행하고, PowerPoint 프로세스가 남지 않습니다.
7. **나머지 기능 이식.** 검색, 편집, 가져오기·내보내기, MariaDB 동기화, 리모컨 단축키를 옮깁니다.
   - 통과 기준: 기존 앱 없이 한 달간 예배를 진행합니다.

## 9. AI 코딩 도구에 넣을 프롬프트

아래 문장을 프로젝트 규칙 파일이나 첫 요청에 넣습니다. 한 번에 전체를 만들게 하지 말고, 8장의 단계 하나씩 요청합니다.

```text
우리는 교회 방송실용 프레젠테이션 앱을 만든다. 아래 규칙을 항상 지켜라.

[구조]
1. 솔루션은 프로젝트 3개다.
   - EasiSlides.App: WinUI 3, net11.0-windows10.0.19041.0, PublishAot=true
   - EasiSlides.OfficeBridge: 콘솔 앱, net11.0-windows, AOT 사용 안 함, PowerPoint COM Interop 담당
   - EasiSlides.Contracts: 두 프로젝트가 공유하는 메시지 타입, IsAotCompatible=true
2. App에는 COM Interop 코드를 절대 넣지 마라. Office 작업은 모두 OfficeBridge에 named pipe로 요청한다.
3. 메시지 직렬화는 System.Text.Json 소스 생성기(JsonSerializerContext)를 쓴다.
4. App에서는 런타임 리플렉션을 쓰지 마라. XAML 바인딩은 {x:Bind}만 쓰고, MVVM은 CommunityToolkit.Mvvm 소스 생성기를 쓴다. AOT 경고는 0개여야 한다.
5. 식별자와 주석은 영어로 쓴다.

[모니터와 창]
6. DisplayArea.FindAll()로 모니터를 찾고 인덱스 for 문으로 순회한다. DisplayArea.CreateWatcher()로 연결 변경을 감시한다.
7. 역할은 Control, Projector, Prompter, Broadcast 네 가지다. 어느 모니터가 어떤 역할인지는 사용자가 정하고, 장치 식별자와 함께 저장한다. 모니터 번호를 역할로 고정하지 마라.
8. 송출 창은 AppWindow.Move()로 대상 모니터에 옮긴 뒤 AppWindowPresenterKind.FullScreen을 적용한다. 모니터가 없는 역할의 창은 만들지 않는다.
9. 송출 창의 내용은 1920x1080 고정 캔버스를 Viewbox로 감싼다.
10. 조종관 썸네일은 Stretch="Uniform", DecodePixelWidth = 320 x 화면 배율로 로드한다. DecodePixelWidth는 UriSource보다 먼저 설정한다.
11. Prompter 창은 검은 배경에 TextBlock만 쓴다. Broadcast 창은 #00FF00 배경에 하단 자막만 그리고, 그림자 대신 불투명한 검은 외곽선을 쓴다.

[PPT]
12. PPT를 불러올 때 OfficeBridge가 슬라이드마다 TimeLine.MainSequence, TimeLine.InteractiveSequences, msoMedia 도형, SlideShowTransition, 노트 텍스트를 읽어 Static / Stepped / Live 중 하나로 분류한다. 사용자가 파일 단위로 등급을 강제할 수 있게 한다.
13. Static: Slide.Export로 프로젝터 해상도에 맞는 PNG를 뽑아 캐시 폴더에 저장한다. 캐시 키는 파일 경로, 수정 시각, 크기다. 추출은 백그라운드 큐에서 한 장씩 하고 진행률을 보고한다.
14. Stepped: 원본을 복사한 파일에서 클릭 단계마다 도형 표시 여부를 바꿔 가며 PNG를 뽑는다. 내장 동영상은 pptx(zip)에서 파일을 꺼내고, 도형 위치를 슬라이드 크기 대비 비율로 저장해 같은 자리에 MediaPlayerElement로 재생한다. 자르기, 자동 재생, 반복, 음량 설정을 반영한다.
15. Live: 실제 PowerPoint 슬라이드쇼 창을 Projector 모니터 좌표에 띄운다. SetParent는 쓰지 마라. 좌표는 포인트 단위이므로 모니터 배율로 환산한다. SlideShowNextSlide, SlideShowNextClick, SlideShowEnd 이벤트를 App에 전달해 조종관과 동기화한다.
16. 송출 창은 Image 3개(이전, 현재, 다음)를 겹쳐 두고 Opacity로 전환한다. 메모리에는 이 3장만 디코드해 둔다.
17. OfficeBridge는 자기가 띄운 POWERPNT.EXE의 프로세스 ID를 App에 알린다. 브리지가 응답하지 않으면 App이 그 프로세스만 종료하고 브리지를 다시 띄운다. COM 객체는 모두 명시적으로 해제한다.

[동영상]
18. 동영상은 MediaPlayerElement로 재생하고 자막은 그 위에 TextBlock으로 겹친다. 동영상 뒤에는 XAML 요소를 두지 마라.
19. MediaPlayer.AudioDevice를 설정에 저장된 장치로 지정한다. 장치가 없으면 기본 장치로 바꾸지 말고 경고를 띄운다.
```
